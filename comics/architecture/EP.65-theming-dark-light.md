# 漫画 · 第 65 话 主题与明暗体系的构建

> 对应正文：[docs/architecture/03-theming-dark-light.md](../../docs/architecture/03-theming-dark-light.md) ｜ 原画：[EP.65-theming-dark-light.svg](./EP.65-theming-dark-light.svg)

## 登场角色

- **像素酱**：CSS 造型师。本话她给内容后台补暗色主题，结果用户反馈「先白闪一下」「弹窗还是白底」。
- **码叔**：经验丰富的老工程师。他提醒：主题不是颜色集合，而是系统偏好、应用主题、组件适配三层契约。

## 剧情梗概

暗色主题上线后问题集中在三处：主题脚本在 body 末尾执行，首帧先浅色；部分组件写死 `#fff`；Portal 浮层挂到 body 后没有继承主题。码叔把主题引导脚本移到 head 内联执行，组件改为消费语义令牌，浮层显式复制主题属性，并给关键文本加了对比度自检。

## 分格解读

### 格1 · 痛点现场

首屏闪白不是「样式加载慢」，而是主题决策发生得太晚。只要 `data-theme` 在首帧之后才写入，浏览器就一定先用默认浅色画一帧。弹窗则是另一个边界问题：Portal 脱离了页面节点，主题作用域没有跟过去。

### 格2 · 机制登场

三个层次要分开：系统偏好由 `prefers-color-scheme` 与 `color-scheme` 表达；应用主题由 `[data-theme]` 加语义令牌映射；组件只消费语义令牌，不判断明暗。`light-dark()` 可按 `color-scheme` 取值，减少重复变量，但要求主题严格二分。切换时保存的是用户模式（light/dark/system），不是解析后的明暗值。

### 格3 · 落地收束

防闪的关键顺序是：head 内联脚本读 `localStorage` 与系统偏好 → 立刻写 `document.documentElement.dataset.theme` → CSS 在 `:root[data-theme="dark"]` 下重绑语义令牌。Portal 容器显式复制主题属性。示例里实时显示前景与背景的对比度，暗色选中行从不足 2:1 修到 ≥4.5:1。

## 码叔划重点

1. 系统偏好只是默认输入，应用主题负责重绑语义层，组件只消费令牌。
2. 保存 `system` 模式，系统切换时才能继续跟随。
3. 首屏脚本必须内联在 `<head>`，任何外部脚本或后置执行都会闪。
4. `color-scheme: light dark` 管的是系统 UI（滚动条、表单控件），不会自动改自定义颜色。
5. 对比度要脚本校验：正文 4.5:1、大字 3:1，不能凭「看起来还行」。
6. 暗色不是简单反相，需重调色相、饱和度与阴影。

## 自测一题

**问**：为什么主题切换要保存 `system`，而不是直接保存解析后的 `dark` / `light`？

**答**：保存 `system` 保留了「跟随系统」这一意图。若直接存解析结果，用户在系统里切换明暗后页面不会跟随，因为应用已经把它当成一次手动选择。正确做法是同时记录模式与解析值：模式用于 UI 与持久化，解析值用于当前渲染。
