首屏渲染与白屏治理（关键路径 / 字体 / 资源提示） ​

面向前端开发人员的首屏性能参考资料 —— 用户不会等一个"正在加载"的空白页。本章拆开从点击链接到看见内容的关键渲染路径，讲清 CSS 与同步 JS 如何阻塞渲染、字体 FOIT/FOUT 的成因与 font-display 的选择、骨架屏 / SSR / 流式渲染的分工，以及 SPA 白屏的四大根因与一套可落地的白屏监控方案（FCP + MutationObserver + 超时 + 错误兜底）。

1. 概念解释 ​

1.1 什么是白屏：从"导航开始"到"看见内容" ​

白屏指用户已发起导航（点击、输入 URL、刷新），但屏幕上没有任何有意义内容的持续状态。通常拆成两段：① 导航到首字节（TTFB），用户看到地址栏加载动画；② 首字节到首次内容绘制（FCP），HTML 已到达但还没有文字或图片画出——后者是真正意义上的白屏期。

判定方式说明风险
仅看 FCPfirst-contentful-paint 缺失或超过阈值只画了空容器时可能误判
FCP + 内容检查再检查主容器是否有可见文本 / 图片更准确，但检测更重
FCP + DOM 变化用 MutationObserver 观察有效节点变化加载动画也会产生变化，需过滤
超时兜底3 秒内既无 FCP 也无有效变化 → 判定白屏弱网下可能误报，需结合网络维度

本章采用组合判定：FCP 缺失 + 有效 DOM 变化过少 + 超过 3 秒 → 疑似白屏；同时挂 error / unhandledrejection 兜底，因为"渲染了但立刻崩掉"在用户眼里同样是白屏。

1.2 关键渲染路径（Critical Rendering Path） ​

HTML 字节 ──解析──▶ DOM
CSS 字节 ──解析──▶ CSSOM
DOM + CSSOM ──▶ Render Tree（只含可见节点）──▶ Layout ──▶ Paint ──▶ Composite

关键约束：

  1. CSS 是渲染阻塞资源：样式表未解析完，浏览器不绘制任何内容——因为不知道元素该长什么样。<head> 里的大 CSS、@import 链、阻塞式字体 CSS 都会直接推迟首屏。
  2. 同步 JS 阻塞 HTML 解析：无 async/defer 的 <script src> 让解析器停下来下载并执行，放在 <head> 会把整个首屏解析推迟到脚本完成。
  3. JS 还会等待 CSSOM：样式表在脚本之前时，脚本执行前必须等 CSSOM 构建完成（脚本可能读样式），于是"CSS 慢"会同时拖慢"JS 执行"，形成串联等待。
  4. 不是所有资源都在关键路径：async / defer 脚本、首屏外 lazy 图片、prefetch 都不阻塞首屏；但 LCP 主图若在首屏却被懒加载，反而会人为推迟首屏。

1.3 CSS 与同步 JS 的阻塞差异 ​

资源阻塞解析阻塞渲染何时执行建议
普通 <script>✓✓ 间接下载完立即执行仅首屏关键小脚本放头部
<script async>✗可能（占用主线程）下载完立即执行，顺序不保证独立第三方（统计、广告）
<script defer>✗✗DOM 解析完后、DOMContentLoaded 前按序业务主包首选
<script type="module">✗（默认 defer 语义）✗依赖解析后现代构建产物默认形态
<link rel="stylesheet">✗✓CSSOM 完成关键 CSS 内联，其余异步
@import—✓（串行）依赖样式表解析后生产环境避免，改并行 <link>

一个常被忽略的细节：CSS 阻塞的是"渲染"与"依赖它的脚本执行"，不阻塞 HTML 解析。所以大 CSS 放头部时解析仍在继续，只是"看不见"——用户感知就是白屏。

1.4 字体：FOIT、FOUT 与 font-display ​

  • FOIT（不可见文本闪烁）：字体未就绪期间文字完全不显示，字体到达后一次性出现。观感是"白块 → 突然有字"，慢网下可能持续数秒。
  • FOUT（无样式文本闪烁）：先用回退字体显示文字，Web 字体到达后替换。文字始终可读，但字体变化会引起宽度 / 换行变化。
值block 期（文字不可见）swap 期（回退字体可见）适用场景
auto浏览器默认（通常接近 block）由浏览器决定不推荐依赖
block约 3s无限，直到字体到达品牌标题等宁可不显示的少数场景
swap0无限，到达即替换正文首选，保证内容立即可读
fallback约 100ms约 3s，超时后本次不再替换"短暂回退、尽快换回"的折中
optional约 100ms0（本期不用 Web 字体）字体非关键、弱网优先稳定

swap 的代价是 CLS：回退字体与 Web 字体度量不同，替换瞬间文字宽度变化会带动行高 / 换行。缓解手段：选度量接近的回退字体栈（system-ui 优先）、用 size-adjust / ascent-override 修正度量、preload 字体缩短 swap 窗口；标题可接受 block，正文坚决 swap。

1.5 骨架屏、SSR 与流式渲染 ​

方案原理优点代价 / 风险
骨架屏占位块 + 微光动画先画出"假布局"，数据到达后替换首屏立即有画面，感知等待下降；成本低与真实布局不一致会造成二次跳动
SSR服务端拼好 HTML 再返回FCP / LCP 显著提前，利于 SEO服务端压力与缓存复杂度上升，需处理 hydration
流式 SSR先发"壳"（导航、骨架、静态区），再分块推送内容首字节即可渲染，长尾数据不阻塞首屏需框架支持（如 React 18 renderToPipeableStream）

三者不互斥：成熟电商首屏常见"流式 SSR 输出页头与骨架 → 关键数据块随到随渲染 → 非关键模块客户端懒加载"。骨架屏在这里是"块与块之间的过渡"，而不是整页的遮羞布。

1.6 SPA 白屏的四大根因 ​

根因典型表现排查入口
包体过大首屏 JS 数 MB，解析 + 执行数秒构建体积分析、resource 条目、longtask
接口瀑布先等鉴权、再等配置、再等列表，串行 4~5 个请求Network waterfall、mark/measure 分段
运行时异常渲染报错、依赖 404、hydration mismatch，组件树挂掉error / unhandledrejection、错误边界
路由 / 部署问题publicPath 配错、CDN 旧缓存、路由守卫死循环资源 404 日志、灰度对比、路由埋点

SPA 的特殊性：HTML 本身几乎是空的，首屏完全依赖 JS 执行，包体 / 接口 / 异常任一环出问题，用户看到的就是纯白。因此 SPA 必须有错误兜底 UI，而不是让异常冒到顶层后整页空白。

1.7 资源提示与预渲染 ​

提示做的事用在首屏的哪里
dns-prefetch只做域名解析便宜预热，第三方域多时兜底
preconnectDNS + TCP + TLS关键第三方域，控制在 3~4 个
preload强制提前拉当前页确定要用的资源LCP 图、关键字体（必须 crossorigin）、关键 CSS
prefetch低优先级拉下一页可能用的资源高概率的下一步导航
modulepreload预取并解析 / 编译 ES 模块启动即依赖的模块链
Speculation Rules预获取或预渲染下一页MPA 的"点击即见"，见 Speculation Rules

误用代价：preload 了没用的资源会在 Console 报警并白耗流量；preconnect 过多会占满连接池；prefetch 在移动端会消耗用户套餐。收益来自"把对的资源放到对的时机"，不是提示越多越快。预渲染能把"下一页 LCP"压到接近 0，但只适用于同源、可预测、无副作用的页面（注意统计上报等副作用被重复执行）。

1.8 content-visibility：让"看不见的部分"不参与首屏 ​

css
.section {
  content-visibility: auto;
  contain-intrinsic-size: auto 400px; /* 占位高度，避免滚动条跳动 */
}

它让浏览器跳过屏幕外元素的布局与绘制，接近视口时再按需渲染。优化的是整页渲染成本，对首屏的直接收益有限，但能降低长页面首次布局耗时；必须提供 contain-intrinsic-size，否则滚动条长度会随滚动不断变化。观察 DOM / 布局变化的通用思路见 Observer 三件套。

2. 语法说明 ​

2.1 关键路径的时间线 ​

text
navigationStart → DNS / TCP / TLS → requestStart → responseStart（TTFB）
→ responseEnd → HTML 解析 → [CSS 下载 + CSSOM] / [同步 JS 下载 + 执行]
→ first-paint / FCP → LCP
js
const nav = performance.getEntriesByType('navigation')[0];
console.table({
  TTFB: nav.responseStart,
  HTML下载: nav.responseEnd - nav.responseStart,
  DOM解析: nav.domContentLoadedEventEnd - nav.responseEnd,
  load: nav.loadEventEnd,
});

2.2 资源提示的标准写法 ​

html
<head>
  <!-- 关键第三方域：先握手；同源不需要 preconnect -->
  <link rel="preconnect" href="https://fonts.example.com" crossorigin>
  <link rel="dns-prefetch" href="//track.example.com">

  <!-- 当前页确定要用的资源：LCP 图 + 关键字体 -->
  <link rel="preload" href="/hero.avif" as="image" fetchpriority="high">
  <link rel="preload" href="/brand.woff2" as="font" type="font/woff2" crossorigin>

  <link rel="modulepreload" href="/app.mjs">
  <link rel="prefetch" href="/next-page.json">
</head>
属性必填项常见错误
preload as="image"as 与真实类型一致写成 as="fetch" 导致二次下载
preload as="font"必须 crossorigin（即使同源）漏写 → 字体被下载两次
preload as="style"通常配 onload 切换为正式样式表只 preload 不 stylesheet，资源永不生效
preconnect跨域时加 crossorigin对同源做 preconnect，收益接近 0
modulepreload只对 ESM 有意义对普通脚本使用等于无效提示
html
<!-- 异步加载非关键 CSS -->
<link rel="preload" href="/non-critical.css" as="style"
      onload="this.onload=null;this.rel='stylesheet'">
<noscript><link rel="stylesheet" href="/non-critical.css"></noscript>

2.3 font-display 与字体度量修正 ​

css
@font-face {
  font-family: "Brand Sans";
  src: url("/brand.woff2") format("woff2");
  font-weight: 400 700;         /* 可变字体范围 */
  font-display: swap;           /* 正文：先回退，到达即换 */
  size-adjust: 96%;             /* 修正回退字体整体尺寸 */
  ascent-override: 92%;
  descent-override: 24%;
  line-gap-override: 0%;
}
body { font-family: "Brand Sans", system-ui, -apple-system, "PingFang SC", sans-serif; }
/* 标题：@font-face 用 block，避免"字体突变"破坏品牌观感 */

size-adjust / ascent-override 等描述符用于修正回退字体的度量，让 swap 时的宽度变化更小，是降低字体相关 CLS 的有效手段；数值需按具体字体实测，不能照抄。

2.4 Speculation Rules：预渲染下一页 ​

html
<script type="speculationrules">
{
  "prerender": [{
    "source": "document",
    "where": { "and": [
      { "href_matches": "/product/*" },
      { "selector_matches": "a[data-prerender]" }
    ] },
    "eagerness": "moderate"
  }],
  "prefetch": [{ "source": "list", "urls": ["/help", "/about"] }]
}
</script>

限制：只对同源 URL 生效；file:// 下不工作（需 http://localhost 或 HTTPS）；预渲染页面的脚本会真实执行，必须确保没有"进入即写数据"的副作用；eagerness 三档控制积极度。完整语法见 Speculation Rules。

2.5 白屏检测器：FCP + MutationObserver + 超时 + 错误兜底 ​

js
(function () {
  const THRESHOLD = 3000;
  const startedAt = performance.now();
  let fcp = null, meaningfulMutations = 0, reported = false;

  // 1) FCP：性能条目（老浏览器降级为纯超时判定）
  try {
    new PerformanceObserver((list) => {
      for (const e of list.getEntries()) {
        if (e.name === 'first-contentful-paint') fcp = e.startTime;
      }
    }).observe({ type: 'paint', buffered: true });
  } catch (_) {}

  // 2) 有效 DOM 变化：过滤加载动画自身的抖动
  const mo = new MutationObserver((records) => {
    for (const r of records) {
      if (r.type !== 'childList' || !r.addedNodes.length) continue;
      const meaningful = [...r.addedNodes].some((n) =>
        n.nodeType === 1 &&
        !n.matches?.('.skeleton, .loading, .spinner'));
      if (meaningful) meaningfulMutations++;
    }
  });
  mo.observe(document.documentElement, {
    subtree: true, childList: true, characterData: true,
  });

  // 3) 错误兜底：渲染崩了也是白屏
  const onError = (reason) => report('error', String(reason));
  addEventListener('error', (e) => onError(e.message), true);
  addEventListener('unhandledrejection', (e) => onError(e.reason));

  // 4) 超时判定
  const timer = setTimeout(() => {
    if (reported) return;
    const blank = (!fcp || fcp > THRESHOLD) && meaningfulMutations === 0 &&
      !document.querySelector('main')?.innerText.trim();
    if (blank) report('blank-screen', 'no-fcp-and-no-content');
  }, THRESHOLD);

  function report(type, detail) {
    if (reported) return;
    reported = true;
    clearTimeout(timer); mo.disconnect();
    const payload = {
      type, detail, fcp,
      elapsed: Math.round(performance.now() - startedAt),
      mutations: meaningfulMutations, page: location.pathname,
    };
    navigator.sendBeacon?.('/rum-blank',
      new Blob([JSON.stringify(payload)], { type: 'application/json' }));
  }
})();

逐段说明：fcp 只判断"是否画过东西"，是否"有意义"要配合 innerText 检查；MutationObserver 统计有效节点新增，必须过滤骨架 / loading 自身，否则永不停的 spinner 会让检测器永远认为"有变化"；reported 保证只报一次；出错时立即上报并断开观察器，避免泄漏。

2.6 骨架屏与 content-visibility ​

css
.skeleton {
  border-radius: 8px;
  background: linear-gradient(90deg, #eef2f7 25%, #e3e9f1 37%, #eef2f7 63%);
  background-size: 400% 100%;
  animation: shimmer 1.4s ease infinite;
}
@keyframes shimmer { from { background-position: 100% 0; } to { background-position: 0 0; } }
@media (prefers-reduced-motion: reduce) {
  .skeleton { animation: none; background: #eef2f7; }
}
.long-section { content-visibility: auto; contain-intrinsic-size: auto 420px; }

骨架屏动画要尊重 prefers-reduced-motion；content-visibility 只用于首屏之外，首屏元素加上会推迟渲染与 LCP。

4. 使用场景示例 ​

4.1 营销落地页的关键路径压缩 ​

场景描述：首屏有品牌字体、大图、统计脚本与大量非关键模块。目标是把关键路径缩到"HTML + 关键 CSS + LCP 图"三件事。

html
<head>
  <!-- 关键 CSS 内联：首屏样式约 6KB，随 HTML 到达 -->
  <style>
    html{font-family:system-ui,sans-serif;background:#0b1020;color:#fff}
    .hero{min-height:60vh;display:grid;place-items:center}
    .hero img{width:100%;height:auto;aspect-ratio:16/9;object-fit:cover}
  </style>

  <!-- 非关键 CSS 异步加载 -->
  <link rel="preload" href="/rest.css" as="style" onload="this.rel='stylesheet'">
  <noscript><link rel="stylesheet" href="/rest.css"></noscript>

  <!-- 字体：preload + swap，既快又不挡文字 -->
  <link rel="preload" href="/brand.woff2" as="font" type="font/woff2" crossorigin>

  <!-- 第三方：只 preconnect 关键域，统计域仅 dns-prefetch -->
  <link rel="preconnect" href="https://cdn.example.com" crossorigin>
  <link rel="dns-prefetch" href="//track.example.com">

  <!-- 业务脚本 defer，不阻塞解析 -->
  <script src="/app.js" defer></script>
  <script src="https://track.example.com/t.js" async></script>
</head>
<body>
  <header>...</header>
  <section class="hero">
    <img src="/hero.avif" width="1600" height="900"
         fetchpriority="high" decoding="async" alt="首屏主视觉">
  </section>
  <main>...</main>
</body>

逐段注释：内联关键 CSS 消灭了"等 CSS 才能画"的往返；非关键 CSS 用 preload + onload 异步化，noscript 保证无 JS 环境仍有样式；字体 preload 与 swap 同时用，既缩短 swap 窗口又保证文字立即出现；defer 让业务脚本不阻塞解析，async 让统计脚本独立执行、不排队。

预期效果：FCP 通常在 1s 内，LCP 由主图决定；弱网下文字立即以系统字体可见，字体到达后替换。

5. 实际应用案例分析 ​

案例一：内容站 FCP 3.6s → 1.1s ​

背景：资讯站首屏 FCP p75 = 3.6s，4G 下经常白屏 4s 以上。Lab（CPU 4x + 网络 4G）拆解：

阶段耗时问题
TTFB620msCDN 未命中时到 1.2s
HTML 下载180ms正常
CSS（2 个样式表 + 1 个 @import）1.4s@import 串行，且含整站样式
同步 JS（头部 3 个脚本）900ms统计、埋点、polyfill 都在头部
字体 block 期2.8s标题字体 block，正文也受影响
首次绘制3.6s以上串联

优化：移除 @import，关键 CSS 内联（5.8KB）+ 非关键异步；头部脚本全改 defer，统计改 async 移尾部；字体 swap + preload + 度量修正；封面图补 width/height 与 fetchpriority="high"，去掉误加的 lazy；图片 CDN 加 1 个 preconnect。结果：FCP p75 3.6s → 1.1s，LCP 4.2s → 2.3s，CLS 0.18 → 0.03。收益几乎全部来自"移除关键路径上的阻塞"，而不是加更多预加载。

案例二：SPA 白屏 P1 事故复盘 ​

背景：某后台系统发版后约 7% 用户打开首页白屏，重试后恢复。白屏检测器上报中 82% 带 error，信息为 Failed to fetch dynamically imported module；对账版本发现集中在"发版后 10 分钟内 + 未刷新页面"的会话——旧页面的路由指向旧 chunk，新版本部署后旧 chunk 被删除，动态 import() 404。本地复现一致。

措施说明
保留最近 2 个版本的 chunk旧产物不立即删除，给缓存中的旧页面留窗口
监听 chunk 加载失败命中后 location.reload() 一次（带去重标记）
路由切换加 loading 态加载失败时至少不是纯白
错误边界 + 兜底页任何渲染异常都有"重试"入口
发版通知检测到新版本时提示刷新

结果：白屏率 7% → 0.3%，剩余样本主要是用户主动断网。教训：SPA 白屏监控必须同时覆盖"没画出来（FCP 缺失）"与"画了但崩了（运行时异常）"，只监控 FCP 会漏掉后者。

案例三：font-display: block 造成的"假白屏" ​

某品牌站为"字体必须正确"全站 block。弱网下字体 4s 才到，正文 4s 内完全不可见，用户截图反馈"白屏"——实际上 HTML 早已到达、布局也完成了。修复：正文 swap、大标题 block 但配合 preload，并用 size-adjust 修正回退字体。修复后 FCP 不变，但"用户看到文字"的时间从 4s 降到 0.6s。FCP 不等于"用户看到有用内容"，字体策略必须按内容重要性分级。

6. 最佳实践与常见坑 ​

6.1 ✗ 与 ✓ 对比速查 ​

✗ 反例✓ 正例
CSS<head> 塞整站 CSS + @import 链关键 CSS 内联，非关键 preload + onload 异步
JS头部多个同步脚本业务 defer、独立三方 async，首屏只留必要逻辑
字体全站 font-display: block正文 swap、标题按需 block，配 preload 与度量修正
LCP 图统一加 loading="lazy"首屏图 fetchpriority="high" + 禁 lazy + 写宽高
SPA 首屏HTML 里只有空 #app内置骨架屏 + 错误边界 + 路由分割
资源提示见资源就 preload只 preload 当前页确定要用的资源，字体带 crossorigin
白屏判定只看 FCP 是否缺失FCP + 有效 DOM 变化 + 超时 + 错误兜底
长页面所有楼层一次性布局首屏外 content-visibility: auto + 占位高度

6.2 十二条落地守则 ​

  1. 先画关键路径图再优化：逐段测量 DNS/TTFB/HTML/CSS/JS/字体/图片，找出串联等待最长的一段，而不是盲目加 preload。
  2. 关键 CSS 内联、非关键异步：首屏样式通常 5–10KB，内联收益远大于多一次请求；剩余样式用 preload + onload 切换 rel。
  3. 生产环境禁止 @import：它会形成串行下载链，每多一层多一个往返；用并行 <link> 或构建期合并。
  4. 同步脚本移出关键路径：业务代码 defer，独立第三方 async；只有必须在渲染前执行且体积很小的逻辑才允许同步。
  5. 字体策略按内容分级：正文 swap 保证可读，标题可 block 但必须 preload；同时修正回退字体度量，降低 swap 的 CLS。
  6. LCP 资源要早发现、早请求、高优先级：写在 HTML 里（而非 CSS 背景或 JS 注入）、不加 lazy、fetchpriority="high"，必要时 preload。
  7. 骨架屏与真实布局同构：宽度比例、行高、圆角尽量一致，否则数据到达仍会二次跳动；骨架动画尊重 prefers-reduced-motion。
  8. SSR / 流式优先输出"壳"：导航、页头、骨架先到，长尾数据后到；不要等所有接口完成才发送整页。
  9. SPA 必须有错误兜底 UI：错误边界 + chunk 加载失败重试 + 版本更新提示，三者缺一都会把异常变成纯白。
  10. 资源提示宁少勿滥：preconnect ≤ 3~4 个关键域；preload 只放当前页确定使用的资源；上线后检查 "preloaded but not used" 警告。
  11. 白屏监控组合判定：FCP 缺失 ≠ 白屏（可能只画了空容器），有 FCP ≠ 没问题（可能随后崩了）；超时 + DOM 变化 + 错误一起看。
  12. content-visibility 只用于首屏外：首屏元素加上会推迟渲染与 LCP；必须配 contain-intrinsic-size，否则滚动条会跳。
