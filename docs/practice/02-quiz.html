1. 概念解释 ​

1.1 三级能力模型 ​

级别能力题型通过标准
L1 识记知道属性、语法与默认值单选 / 判断80%
L2 机制能解释规则背后的计算过程单选 / 排序70%
L3 因果能推断改动带来的连锁后果场景分析60%

1.2 为什么按级划分 ​

「会用」与「精通」的差别在于：能否预测未见过的情况。L1 题测记忆，L2 题测机制，L3 题测因果推断。只刷 L1 会产生「都见过」的错觉，遇到线上问题仍然无从下手。

1.3 使用建议 ​

先做 L1 定位盲区，再用 L2 验证机制，最后用 L3 检验迁移能力。错题按主题归档，回到对应正文补齐，而不是背答案。

2. 语法说明 —— 题型、判分与使用方式 ​

2.1 题型 ​

  • 单选：四个选项中只有一个符合规范行为。
  • 判断：一句话陈述，判断对错并说明理由。
  • 排序：给出若干步骤，要求按执行顺序排列。
  • 场景分析：给一段代码或现象，写出原因与修复方向。

2.2 判分原则 ​

L1 只看结论；L2 要求写出关键机制；L3 要求同时给出「原因 + 修复 + 验证方式」。示例页面按单选自动判分，L3 场景题提供参考解析。

2.3 抽题策略 ​

3. 浏览器兼容性 ​

题库涉及的特性按 2026 年基线作答：

  • :has()、容器查询、子网格、@layer、@scope、popover、View Transitions 已进入 Baseline 新可用。
  • CSS 锚点定位仍属增强能力，答题时应考虑兜底。
  • 100svh、light-dark()、@starting-style 在主流引擎可用，旧环境需降级。
  • 性能 API（PerformanceObserver、longtask）在 Chromium 系更完整，跨引擎需回退方案。

4. 分级题库与答案 ​

L1 · 识记（15 题） ​

1. box-sizing: border-box 的作用？ 答案：width / height 包含内容、内边距与边框；默认的 content-box 只含内容。

2. flex: 1 展开后是什么？ 答案：flex-grow: 1、flex-shrink: 1、flex-basis: 0%。

3. Grid 中 1fr 的含义？ 答案：按剩余空间的比例分配；fr 在计算前会先扣除固定轨道与间距。

4. 绝对定位元素的包含块如何确定？ 答案：最近的非 static 祖先的内边距盒；若没有，则为初始包含块。

5. 普通流中相邻块的外边距会怎样？ 答案：发生折叠，取较大值（正负值另有规则）。

6. 选择器特异性 #id .class tag 是多少？ 答案：1-1-1（ID、类、元素各一层）。

7. :has() 解决什么问题？ 答案：让父级根据后代或后续兄弟的状态设置样式，此前只能靠 JS。

8. 容器查询与媒体查询的核心区别？ 答案：容器查询按祖先容器尺寸判断，媒体查询按视口 / 设备判断。

9. 为什么交互优先用 <button> 而不是 <div>？ 答案：原生按钮自带角色、焦点与键盘激活行为。

10. 装饰性图片的 alt 应怎么写？ 答案：alt=""，让读屏跳过。

11. loading="lazy" 的效果？ 答案：图片接近视口时才加载，减少首屏请求与带宽。

12. defer 与 async 的差别？ 答案：defer 保证按顺序、在解析完成后执行；async 下载完就执行，顺序不确定。

13. LCP 衡量什么？ 答案：视口内最大内容元素完成渲染的时间。

14. 造成 CLS 的常见原因？ 答案：图片 / 广告未预留尺寸、字体替换、动态插入内容导致布局偏移。

15. popover 的基础用法？ 答案：触发器加 popovertarget，目标元素加 popover 属性；也可用 showPopover()。

L2 · 机制（15 题） ​

16. Flex 子项为什么会被长文本撑破？ 答案：子项默认 min-width: auto，不会小于内容最小宽度；显式 min-width: 0 才允许收缩并省略。

17. BFC 能解决什么？ 答案：隔离外边距折叠、包含浮动子元素、阻止与外部布局互相影响。

18. position: fixed 的包含块一定是视口吗？ 答案：不一定。祖先若创建了包含块（如 transform、filter、will-change），固定定位会相对该祖先。

19. @layer 的层顺序由什么决定？ 答案：由首次声明顺序决定；未分层样式优先级高于所有层。

20. 层内 !important 的顺序为什么反向？ 答案：规范规定 !important 声明在层叠中按层顺序反转，低层的 !important 反而胜过高层。

21. @scope 在多重作用域命中时如何取舍？ 答案：按「就近原则」，更接近目标元素的根胜出；特异性仍参与比较。

22. 锚点定位不生效时如何兜底？ 答案：基础用相对 / 绝对定位给出近似位置，@supports 内再启用 position-anchor 与 anchor()。

23. 跨文档 View Transitions 的前提？ 答案：同源、两次导航都启用、浏览器支持；还需处理后退与焦点恢复。

24. Speculation Rules 为什么在 file:// 下无效？ 答案：预取 / 预渲染需要 http(s) 环境与同源 / CORS 许可，file:// 不满足。

25. 设计令牌三层各负责什么？ 答案：原始层存值，语义层定角色，组件层暴露接口；主题只重绑语义层。

26. color-scheme 与 light-dark() 的关系？ 答案：color-scheme 决定系统 UI 与 light-dark() 的取值方向；它不会自动改自定义颜色。

27. Tailwind 的 px-4 为什么能覆盖组件类的内边距？ 答案：工具类位于 utilities 层，高于 components 层；分层后先比层顺序。

28. 什么是强制同步布局？ 答案：写样式后立即读几何属性，浏览器被迫同步完成布局，打断批量优化。

29. 创建合成层的常见条件？ 答案：3D 变换、will-change、滤镜、透明度动画、position: fixed 等；具体由浏览器决定。

30. ResizeObserver 循环报错的原因？ 答案：回调中修改尺寸，再次触发观察，超过浏览器循环限制后报错；应改为异步或去抖。

L3 · 因果推断（10 题） ​

31. 为什么 transform / opacity 动画通常比 width 动画流畅？ 答案：前者在合成阶段处理，不触发布局与重绘；后者改变几何，触发布局并可能连锁重绘。解析需同时说明「合成线程可独立处理」。

32. 为什么 will-change 用多了反而更慢？ 答案：每个声明可能提前创建合成层，层数量上升带来内存、纹理上传与合成开销，甚至层爆炸。

33. 为什么主题脚本必须内联在 <head>？ 答案：首帧渲染前必须写入 data-theme，否则浏览器先用默认主题绘制一帧，产生闪白；外部脚本与后置脚本都太晚。

34. 为什么视觉回归必须遮罩时间戳与随机内容？ 答案：这些区域每次渲染都不同，会产生与回归无关的像素差异；不遮罩会让测试长期失败并被忽略。

35. 为什么性能预算要同时有资源、请求与指标三层？ 答案：资源与请求是可归因输入，指标是最终输出；只有指标无法定位超支来源，只有资源可能省了字节仍然慢。

36. 为什么 :has() 可能带来样式失效风暴？ 答案：后代状态变化需要反向检查祖先是否匹配，影响范围可能扩大；深层嵌套与宽泛选择器会加重失效计算。应缩小作用域、避免在热点路径滥用。

37. 为什么容器查询需要 container-type？ 答案：只有声明为尺寸容器的祖先才能提供查询尺寸；container-type 同时建立包含块与布局隔离，影响尺寸计算。

38. 为什么子网格要求父级也是网格？ 答案：subgrid 继承父网格的轨道定义；父级不是网格时没有可继承的轨道，声明无效。

39. 为什么渐进增强要把增强样式放进 @supports？ 答案：若增强与基础写在一起，旧引擎整段失效，基础布局也不存在；分离后底线始终可用。

40. 为什么「只测最新 Chrome」不足以支撑兼容结论？ 答案：新特性在旧引擎可能整段失效，且兜底路径长期不跑会腐坏；需要兼容矩阵、旧引擎冒烟与强制降级用例。

5. 实际应用案例分析 ​

背景：某团队用题库做新人 onboarding，先做 L1，再按错题分配阅读任务，两周后做 L2 与 L3。

做法：

  1. L1 错题超过 20% 的人，先补 CSS 布局与 HTML 语义两篇；
  2. L2 错题集中在 @layer 与强制同步布局，安排机制篇精读；
  3. L3 用场景题做评审演练，要求写出「原因 + 修复 + 验证」；
  4. 每月复测一次，错题按主题统计，反哺文档修订。

结果：新人独立处理布局与性能问题的周期从 6 周降到 3 周；代码评审中「凭感觉」的意见明显减少，更多意见能指向具体机制。

6. 最佳实践与常见坑 ​

  1. 按级作答：L1 没过就做 L3，只会得到挫败感。
  2. 错题归因到主题：记录「哪篇文档、哪条机制」，而不是只记答案。
  3. L3 必须写验证：没有验证方式的答案，说明还没真正掌握。
  4. 定期复测：间隔重复比一次性刷题有效。
  5. 题库要更新：浏览器基线与规范在变，过期题目会误导。
  6. 不要背选项：选项顺序与措辞应随机化，重点在解析。
