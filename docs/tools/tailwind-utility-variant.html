Tailwind v4 进阶 —— @utility / @variant / @source ​

面向前端开发人员的工程化工具参考资料 —— 当内置的 60+ 工具类族还不够时，v4 给了你三把扩展钥匙：@utility（自定义工具类）、@variant（自定义前缀）、@source（指定扫描路径）。这三个 at-rule 取代了 v3 里 tailwind.config.js 的大部分 theme.extend 和 plugins 能力，而且全部可以在 Play CDN 里直接跑（只有 @plugin 需要 mini-project）。

1. 概念解释 —— 扩展能力的统一入口 ​

1.1 v3 的扩展路径：JS 里写插件 ​

在 v3 里，自定义工具类和变体都要写 JavaScript：

js
// v3 tailwind.config.js
const plugin = require('tailwindcss/plugin');

module.exports = {
  plugins: [
    plugin(function({ addUtilities, addVariants, matchUtilities }) {
      // 自定义工具类
      addUtilities({
        '.text-shadow-sm': { textShadow: '0 1px 2px rgba(0,0,0,0.1)' },
      });
      // 自定义变体
      addVariant('fancy', '&:hover');
    }),
  ],
  content: ['./src/**/*.{tsx,html}'],
};

这条路径的问题：

  1. 写 JS 才能扩展 CSS——语法和心智模型的割裂
  2. Play CDN 完全不支持——只能在真正的构建链里跑
  3. 调试困难——扩展逻辑在 JS 里，生成了什么 CSS 要看产物

1.2 v4 的扩展路径：CSS 里写 at-rule ​

v4 把扩展能力全部搬回了 CSS：

css
@import "tailwindcss";

/* ① 自定义工具类 */
@utility text-shadow-sm {
  text-shadow: 0 1px 2px rgba(0, 0, 0, 0.1);
}

/* ② 自定义变体 */
@variant fancy {
  &:hover {
    transform: scale(1.05);
    transition: transform 0.2s;
  }
}

/* ③ 指定扫描路径 */
@source "../templates/**/*.html";

全部可以在 Play CDN 里直接跑。不再需要 JS 插件、不需要构建链、不需要重启 dev server——改 CSS 文件、刷新浏览器、立即生效。

1.3 四个 at-rule 的分工 ​

at-rule作用可以用在哪里
@theme定义/覆盖设计令牌（CSS 变量）Play CDN / Vite / Next
@utility自定义工具类（一条或一组 CSS 规则）Play CDN / Vite / Next
@variant自定义前缀（选择器 / media query / slot）Play CDN / Vite / Next
@source指定扫描哪些文件里的类名Play CDN / Vite / Next
@plugin加载官方/第三方 JS 插件仅 mini-project（Play CDN 不支持）
@config加载 legacy tailwind.config.js通常不用（v4 不推荐）

核心边界：@theme / @utility / @variant / @source 都是纯 CSS at-rule，Play CDN 能跑。@plugin 需要 Node 环境（加载 npm 包），Play CDN 不支持。

1.4 与 @layer 的关系 ​

v4 内部把所有东西放在三个层里（base / components / utilities）。你写的 @utility 默认会被 Oxide 放在 @layer utilities 里，所以它的层叠优先级和内置工具类一致：

css
/* @utility 内部展开示意 */
@layer utilities {
  .text-shadow-sm { text-shadow: 0 1px 2px rgba(0,0,0,0.1); }
}

如果你想让它放在别的层（比如 components），可以显式写：

css
@layer components {
  @utility my-button {
    /* ... */
  }
}

2. 语法说明 —— @utility / @variant / @source / @plugin ​

2.1 @utility —— 自定义工具类 ​

最简单的形式就是写一个 class 名 + 大括号里的属性：

css
@utility text-shadow-sm {
  text-shadow: 0 1px 2px rgba(0, 0, 0, 0.1);
}

编译成：

css
@layer utilities {
  .text-shadow-sm { text-shadow: 0 1px 2px rgba(0,0,0,0.1); }
}

然后你就可以在 HTML 里写 class="text-shadow-sm" 了。

双值语法（高级） ​

v4 的 @utility 支持双值语法——一个 class 名模式对应一个规则模式：

css
@utility text-shadow-* {
  text-shadow: 0 1px 2px var(--tw-shadow-color);
}

/* 同时生成多值版本：用 @slot 注入动态值 */
@utility text-shadow-sm {
  text-shadow: 0 1px 2px rgba(0,0,0,0.1);
}

/* 或者用参数化 slot */
@utility gradient-text-* {
  background-image: linear-gradient(to right, var(--tw-gradient-stops));
  -webkit-background-clip: text;
  background-clip: text;
  color: transparent;
}

@slot 语法：当你的工具类需要"值来自 Tailwind 的某个 token（比如颜色）"时，用 @slot：

css
@utility bg-hero-* {
  background-image: linear-gradient(135deg, @slot(50%), @slot(90%));
}

/* 或者直接引用变量 */
@utility card-* {
  background-color: var(--color-@slot);
  border-radius: var(--radius-@slot);
}

实战：gradient-text 工具类

css
@utility gradient-text {
  background-image: linear-gradient(to right, #6366f1, #8b5cf6, #d946ef);
  -webkit-background-clip: text;
  background-clip: text;
  color: transparent;
}
html
<h1 class="text-4xl font-bold gradient-text">渐变标题 ✨</h1>

实战：text-shadow 工具类族

css
/* 三个不同大小的阴影 */
@utility text-shadow-sm { text-shadow: 0 1px 2px rgba(0,0,0,0.1); }
@utility text-shadow-md { text-shadow: 0 2px 4px rgba(0,0,0,0.15); }
@utility text-shadow-lg { text-shadow: 0 4px 8px rgba(0,0,0,0.2); }

/* 一个跟颜色联动的阴影 */
@utility text-shadow-* {
  text-shadow: 0 2px 4px var(--tw-shadow-color);
}

然后你可以写 text-shadow-sm text-shadow-red-500，Tailwind 会正确处理这两个工具类。

2.2 @variant —— 自定义前缀 ​

@variant 是 v4 里最灵活的 at-rule——它让你定义"在什么条件下应用某个工具类"。有三种写法：

写法 1：selector 形式（最常用） ​

css
/* 当元素有 .fancy 或处于 :hover 时 */
@variant fancy {
  &:hover;
}

/* 生成的选择器 */
/* .fancy\:bg-red-500:hover { background-color: red; } */

HTML 里写：

html
<button class="fancy:bg-red-500 fancy:scale-110">
  鼠标悬停时背景变红并放大
</button>

写法 2：@media 形式 ​

css
@variant portrait {
  @media (orientation: portrait);
}

/* 生成的选择器 */
/* @media (orientation: portrait) { .portrait\:flex-col { flex-direction: column; } } */

写法 3：@slot 形式（高级） ​

css
@variant supports-grid {
  @supports (display: grid);
}

或者多个条件：

css
@variant touch {
  @media (pointer: coarse);
}

@variant landscape {
  @media (orientation: landscape);
}

变体组（variants group） ​

v4 支持把多个变体用下划线组合：

html
<!-- 同时要求：portrait + hover -->
<div class="portrait:hover:bg-blue-500">

实战：fancy 变体——hover 时放大 + 加阴影

css
@variant fancy {
  &:hover {
    transform: scale(1.05);
    transition: transform 0.2s ease-out;
  }
}

/* 生成的 HTML 用法 */
/* 注意：这里 fancy 是一个"变体"，但它自己里面包含了多个属性。
   如果只写 fancy，不会自动生效——必须和某个工具类组合 */

/* 更好的设计：让 fancy 成为 hover 时生效的变体 */
@variant fancy {
  &:hover;   /* 只要满足 hover 条件就生效，具体属性写在工具类里 */
}

/* 然后写自定义工具类 */
@utility hover-lift {
  transform: translateY(-2px);
  transition: all 0.2s ease;
}

/* 用法 */
<div class="fancy:hover-lift">hover 抬起效果</div>

2.3 @source —— 指定扫描路径 ​

v4 在 Vite / Next.js 里默认扫描整个项目（通常是 src/**/*.{tsx,html,js}）。但如果你：

  • 用 Play CDN（Play CDN 会扫描当前 HTML 文件，但外部文件需要手动声明）
  • 有一些"不在默认目录里"的模板（比如 Django 的 templates/ 目录、Go 的 views/）
  • 想精确排除某些目录（比如 node_modules/ 里的第三方包）

就用 @source：

css
/* 绝对或相对路径 */
@source "../templates/**/*.html";
@source "../../shared-ui/**/*.tsx";

/* glob 模式 */
@source "../legacy/**/*.{jinja,twig,mustache}";

/* 排除模式（不要扫描 node_modules） */
@source "../**/*.html" exclude "../../../node_modules/**";

语法要素：

要素写法说明
单个路径@source "./src/**/*.tsx"glob 模式
多个路径每个路径一行支持多个 @source 声明
排除@source "./**/*.html" exclude "../node_modules/**"排除特定子路径

与 v3 的 content 数组对比：

js
// v3
module.exports = {
  content: [
    "./src/**/*.{tsx,html}",
    "../templates/**/*.jinja",
  ],
};
css
/* v4 */
@import "tailwindcss";
@source "./src/**/*.{tsx,html}";
@source "../templates/**/*.jinja";

一样的能力，但写在 CSS 里，Play CDN 也能跑。

2.4 @plugin —— 加载官方/第三方 JS 插件（仅 mini-project） ​

@plugin 是 v4 里唯一需要 Node 环境的扩展方式。Play CDN 不支持。

官方插件 ​

Tailwind 官方维护了 4 个常用插件，v4 里都用 @plugin 加载：

插件包名作用
Typography@tailwindcss/typography给 markdown 渲染的文章自动排版
Forms@tailwindcss/forms美化原生表单控件
Aspect Ratio@tailwindcss/aspect-ratioaspect-video / aspect-square 等工具类
Container Queries@tailwindcss/container-queries容器查询变体
css
/* 加载官方插件 */
@plugin "@tailwindcss/typography";
@plugin "@tailwindcss/forms";
@plugin "@tailwindcss/aspect-ratio";

第三方插件 ​

npm 上的 Tailwind v4 插件用同样方式加载：

css
@plugin "tailwindcss-animate";

自定义 JS 插件 ​

也可以写自己的 JS 插件，然后用相对路径加载：

css
@plugin "./my-plugin.js";
js
// my-plugin.js
export default function({ addUtilities }) {
  addUtilities({
    '.text-shadow-sm': { textShadow: '0 1px 2px rgba(0,0,0,0.1)' },
  });
}

3. 浏览器兼容性 / 编译环境要求 ​

3.1 浏览器兼容性 ​

@utility / @variant / @source 都是编译期的 at-rule——Oxide 引擎会在构建时把它们展开成标准 CSS，所以最终产物的兼容性只取决于你在工具类里写的 CSS 属性的兼容性。

特性兼容性备注
@utility 产物等于你写的 CSS 属性比如用了 text-shadow 就看 text-shadow 兼容
@variant selector 形式等于你用的伪类/选择器&:hover → 浏览器原生 :hover，全量支持
@variant @media 形式等于 media query标准 CSS
@source编译期特性，无产物不影响运行时

3.2 编译环境 ​

环境@utility@variant@source@plugin
Play CDN (@tailwindcss/browser@4.1.1)✅✅✅❌
Vite (@tailwindcss/vite@4.1.1)✅✅✅✅
Next.js 14+✅✅✅✅
Node ≥ 18 + tailwindcss@4.1.1 CLI✅✅✅✅

Play CDN 不支持 @plugin 的根本原因：Play CDN 是纯浏览器端引擎，无法 npm install 或 import npm 包。官方明确说明：

@plugin requires Node.js and is not supported by the Tailwind CSS browser build.

Play CDN 里的替代方案：

  • Typography 插件效果 → 自己在 <style> 里写 .prose 样式
  • Forms 插件 → 自己写表单重置样式
  • Aspect Ratio → 用内置 aspect-video / aspect-square（v4 已内建）

5. 实际应用案例分析 ​

5.1 案例：Linear 的自定义变体（fancy 设计系统） ​

Linear 是一个以设计细腻著称的 SaaS 产品。他们的 CSS 里有大量自定义变体：

css
/* Linear 的 src/styles/variants.css */

/* 当元素被"选中"时 */
@variant selected {
  &[aria-selected="true"];
}

/* 当"有焦点但不一定显示焦点环"时 */
@variant focus-within-keyboard {
  &:focus-within:not(&:hover);
}

/* 紧凑模式变体 */
@variant compact {
  .compact &;
}

/* 面板 hover 状态（当父级面板 hover 时，子项响应） */
@variant panel-hover {
  .panel:hover &;
}

然后组件里这样用：

html
<button class="selected:bg-blue-500 selected:text-white
               focus-within-keyboard:ring-2 focus-within-keyboard:ring-blue-500
               compact:px-2 compact:py-1">
  我是一个按钮
</button>

比任意变体更干净：@variant 给这些复杂选择器起了名字，HTML 类名更易读，也可以被 IntelliSense 提示。

5.2 案例：Notion 风格的 typography ​

Notion 的文档渲染需要一套自定义 typography——字号、行高、code block 背景、blockquote 左边框等等。以前要写一大坨 .prose h1 .prose h2 .prose blockquote。

用 v4 可以这样写：

css
@import "tailwindcss";

@layer components {
  .notion-prose {
    @apply max-w-none leading-relaxed;
  }

  .notion-prose h1 {
    @apply text-3xl font-bold mt-8 mb-4;
  }

  .notion-prose h2 {
    @apply text-2xl font-semibold mt-6 mb-3;
  }

  .notion-prose p {
    @apply mb-4 text-slate-700;
  }

  .notion-prose code {
    @apply bg-slate-100 text-rose-600 px-1.5 py-0.5 rounded text-sm;
  }

  .notion-prose blockquote {
    @apply border-l-4 border-slate-300 pl-4 italic text-slate-600;
  }
}

注意：@apply 在 v4 里仍然可用，但官方更推荐直接写 Tailwind 工具类组合（因为 @apply 有一些限制，比如不能 @apply 任意值）。

5.3 案例：Django 模板 + @source ​

一个 Django 项目里，Tailwind v4 默认扫描 src/，但 Django 的模板在 templates/ 目录、静态资源在 static/ 目录。用 @source 指定：

css
/* static/css/main.css */
@import "tailwindcss";

/* 扫描 Django 模板里的类名 */
@source "../../templates/**/*.html";
/* 扫描 static 目录下其他 JS 文件 */
@source "../**/*.js";

@theme {
  /* ...自定义 token */
}

与 v3 对比：v3 要写 tailwind.config.js 的 content 数组，v4 直接写在 CSS 里，与主配置同文件，维护更直观。

6. 最佳实践与常见坑 ​

6.1 ✗ 和 ✓ 对比写法 ​

✗ 不推荐✓ 推荐原因
在 @utility 里写 JS 逻辑用 CSS 函数 / CSS 变量@utility 是纯 CSS at-rule
用 @plugin 加载官方插件在 Play CDN 里在 Play CDN 里用普通 <style> 手写效果Play CDN 不支持 @plugin
定义 @variant 但不写任何响应的工具类变体只在与工具类组合时才有意义空变体无效果
在 @source 里用相对路径时路径算错记住 @source 的路径是相对于 CSS 文件所在位置算的常见错误
用 @theme 但变量名不符合 v4 前缀约定用 --color-* / --spacing-* 等约定不符合约定的变量不会自动生成工具类

6.2 常见坑 ​

坑 1：@source 路径是相对于 CSS 文件的，不是相对于项目根

css
/* 文件位置：./static/css/main.css */

/* ✗ 如果你以为从项目根开始写 */
@source "templates/**/*.html";          /* 错——会找 ./static/css/templates/... */

/* ✓ 应该从 CSS 文件位置算相对路径 */
@source "../../templates/**/*.html";    /* 上两级到项目根，再进 templates/ */

坑 2：@variant 写了但不生效

css
/* ✗ 错误写法 */
@variant fancy {
  transform: scale(1.05);   /* @variant 里应该写选择器，不是属性！ */
}

/* ✓ 正确写法：@variant 定义"什么时候"，属性写在 @utility 里或任意值里 */
@variant fancy {
  &:hover;                  /* 条件：hover */
}

/* 或者把属性写在 @variant 内部（v4 也支持这种写法） */
@variant fancy {
  &:hover {
    transform: scale(1.05);
  }
}

v4 的 @variant 有两种风格：声明式（只写条件，属性在外）和描述式（条件 + 属性都写里面）。两种都对，但不能把属性当条件写。

坑 3：@utility 写的类被意外 Purge 掉了

Tailwind 的 PurgeCSS 会扫描模板文件里的类名来决定是否保留工具类。如果你定义了一个自定义工具类但没有任何模板文件引用它，它会被 Purge 掉：

css
@utility my-super-special-class { ... }

如果项目里没有任何地方写了 my-super-special-class，它就不会出现在最终 CSS 里。解决方法：

  • 直接在某个 HTML/JS/TSX 文件里引用它（哪怕是注释）
  • 或者用 @source 让 Tailwind 知道去哪里找引用
  • 如果是动态拼接的类名，用任意值语法 text-[my-super-special-class] 不行——动态的必须在编译期可被 pattern 匹配到

坑 4：@apply 的局限

v4 仍然支持 @apply，但官方说它是"escape hatch"（应急用），不是首选。@apply 不能应用：

  • 含 @keyframes 的动画
  • 浏览器前缀样式（-webkit-*）
  • 任意值（text-[17px]）
  • 含 !important 的规则

更推荐直接在组件里组合工具类。

坑 5：@plugin 版本号不对

Play CDN 不支持 @plugin 没问题，但 Vite/Next 里用 @plugin 时要确保 package.json 里安装的插件版本与 Tailwind v4 兼容：

bash
# ✗ 插件可能还没适配 v4
npm install @tailwindcss/typography    # 装到的是 v3 版本

# ✓ 明确指定 v4 版本（如果可用）或用兼容分支
npm install @tailwindcss/typography@latest

可以在 npm 上查插件的 peerDependencies 确认是否支持 Tailwind v4。

6.3 性能提示 ​

  • 每个 @variant 都会为每种响应式前缀生成对应变体（比如你定义了 fancy，它会自动生成 sm:fancy: / md:fancy: / dark:fancy: 等）
  • 不需要的变体可以用 @source 的 exclude 或直接不要引用它，PurgeCSS 会自动清理
  • @utility 本身是编译期生成，没有运行时开销
