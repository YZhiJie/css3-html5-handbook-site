Sass 模块系统：@use / @forward ​

面向前端开发人员的 Sass 进阶参考 —— Dart Sass（1.85.0+）的模块系统是解决旧 @import 四大历史问题的方案：全局变量污染、多次加载、隐式顺序依赖、性能浪费。本章覆盖 @use / @forward / partials / 私有前缀等核心机制，并明确 Tailwind v4 与 Sass 的不兼容边界（2025 年官方声明）。

1. 概念解释 ​

1.1 为什么 @import 必须废弃 ​

在 Sass 的前 14 年里，@import 是唯一的文件组合方式。到了 2017 年，官方终于承认这套机制存在无法修补的四大缺陷：

问题 1：全局变量污染 ​

scss
// file-a.scss
$primary: #3b82f6;
$card-padding: 16px;

// file-b.scss 想复用 $card-padding，但必须先 import file-a
@import 'file-a';
$card-padding: 24px;   // ⚠️ 覆盖了 a 里的同名变量！
// 下游所有文件看到的 $card-padding 都是 24px

在大型项目（几十个 .scss 文件、多人协作）里，这种"隐式全局命名空间"会导致变量被无意覆盖、debug 极其困难。

问题 2：多次加载 ​

scss
// main.scss
@import 'file-a';    // 1 次
@import 'file-b';    // b 里也 import 了 file-a
@import 'file-c';    // c 里也 import 了 file-a

结果：file-a.scss 被编译 3 次，其中的 mixin 和函数被重复展开、重复求值。编译速度下降，产物体积膨胀。

问题 3：加载顺序依赖（隐藏） ​

scss
// components/card.scss
@import 'variables';    // 必须先 import variables
.card { color: $primary; }

每个文件自己管理自己的 import 顺序。你改了 variables.scss 的依赖项（比如加了 @import 'mixins'），其他文件会不会爆？不知道，隐式耦合。

问题 4：性能与 tree-shaking ​

@import 是简单的文件内联——导入一次就是把整个文件内容复制进来。没有"只导我要用的几个函数"的概念，也没有编译缓存。

1.2 @use 带来了什么 ​

模块系统（Module System，从 Dart Sass 1.23 起稳定，1.50+ 全面替代）引入了：

新机制解决的问题
命名空间（use 'math' as math）变量/函数/mixin 默认带命名空间，隔离污染
只加载一次同路径只编译一次，缓存结果
显式 API（show / hide）设计库作者可以精确控制对外暴露什么
partials（_ 前缀）约定：以下划线开头的文件不单独编译，只能被导入
私有成员（$ / _ 前缀）模块内部变量/函数，外部根本不能访问
原生模块（sass:math / sass:string / sass:list / sass:map / sass:color / sass:meta）官方提供标准库，替代社区零散 mixin 集合

1.3 Dart Sass @import 废弃时间线 ​

阶段Dart Sass 版本行为
可用（历史默认）≤ 1.22@import 完全正常
过渡警告1.23 – 1.79@use 可用，@import 继续工作但官方推荐迁移
Phase 4（当前 2026）1.80+@import 产生废弃警告（编译时 yellow warning），官方建议新项目一律用 @use
计划完全移除2026 年底（规划中）@import 语法只保留极小过渡子集，其余报 error

结论：2026 年起点任何新项目，一律不用 @import。存量项目建议制定 1 个 Sprint 内的迁移计划。

2. 语法说明 ​

2.1 @use 完整参数表 ​

@use 的功能非常集中——把一个模块（文件）加载进来，并（可选地）给它起别名 / 引入某些成员 / 改变命名。

scss
// 最简形式：带默认命名空间（文件名去扩展名）
@use 'sass:math';           // → 用 math.div(10, 2)、math.clamp()
@use 'variables';           // → 用 variables.$primary

// 1. 命名空间 as：改名，避免冲突
@use 'sass:math' as m;
$result: m.div(10, 2);

// 2. as *：完全不使用命名空间，成员直接暴露到当前文件
// ⚠️ 等价于老 @import，容易污染全局，慎用；仅适用于 tokens/mixins 这种只有抽象成员的文件
@use 'tokens' as *;
.btn { color: $primary; }   // 直接 $primary，不用 tokens.$primary

// 3. show：只导入指定的函数/mixin/变量（变量用 $ 前缀）
@use 'mixins' as * show flex-center, $max-width;
// 结果：flex-center、$max-width 可见；mixins 里其他内容不可见

// 4. hide：导入除了 hide 列表以外的所有
@use 'mixins' as * hide internal-helper;

// 5. with：给模块传入配置变量（模块里要提前写 $config: default ... !default）
@use 'theme' with (
  $primary: #0ea5e9,
  $scale: 1.1,
);

2.2 原生模块速查表（Dart Sass 1.85） ​

模块名用途高频成员示例
sass:math数学运算math.div($a, $b)、math.clamp($min, $val, $max)、math.percentage()、math.ceil()、math.floor()、math.round()、math.pow($base, $exp)
sass:string字符串处理string.to-upper-case()、string.to-lower-case()、string.unquote()、string.quote()、string.index()、string.slice()
sass:list列表操作list.append()、list.nth()（注意：Sass 列表从 1 开始！）、list.index()、list.join()、list.zip()
sass:map映射表（对象）map.get()、map.set()（注意：返回新 map，不可变！）、map.has-key()、map.keys()、map.values()
sass:color颜色操作（2024 新版）color.channel()、color.adjust()、color.change()、color.opacity()
sass:metaintrospectionmeta.variable-exists()、meta.function-exists()、meta.inspect()、meta.call()、meta.get-function()

为什么 math.div() 重要？

Sass 1.33+ 起，除法运算符 / 被标记为废弃（因为原生 CSS 4 也引入了 / 作为 * 的同级运算符）。2026 年新项目一律用 math.div($a, $b) 代替 $a / $b。

scss
@use 'sass:math';

// ✗ 老写法（会产生 deprecation warning）
$half: 16px / 2;

// ✓ 新写法
$half: math.div(16px, 2);

// clamp 的常见场景：响应式字号
$font-size: math.clamp(16px, 2vw + 12px, 24px);

2.3 partials（下划线前缀文件） ​

约定：文件名以 _ 开头的 .scss 文件称为 partial（分片），不参与独立编译——Dart Sass CLI 只编译没有 _ 前缀的文件。

src/styles/
├── _tokens.scss         ← partial：只被导入，不直接生成 CSS
├── _mixins.scss         ← partial
├── _reset.scss          ← partial（尽管它会产出 CSS，但仍然只通过 main 进入产物）
└── main.scss            ← 入口文件：会被编译成 main.css
bash
# CLI 只编译 main.scss，不会单独编译 _tokens.scss
npx sass src/styles/main.scss dist/main.css

2.4 @forward：设计库的公开 API 边界 ​

@use 是"消费模块"；@forward 是"转导模块"——你写一个"聚合文件"把多个 partials 包装成一个统一的 API：

scss
// abstracts/_all.scss —— 设计库公共入口

// 直接转发（默认公开模块里所有成员）
@forward 'tokens';
@forward 'mixins';

// show：只暴露指定成员（内部实现细节对外隐藏）
@forward 'functions' show px-to-rem, breakpoints;

// hide：暴露除了指定成员外的所有
@forward 'internal-helpers' hide private-func;

// 批量改名：前缀避免冲突
@forward 'utils' as u-*;
// 消费方看到的是 u-px-to-rem、u-breakpoints

消费方只需要一行：

scss
// main.scss
@use 'abstracts/all' as *;   // 一次拿到所有公共 tokens/mixins/functions
.btn { color: $primary; @include flex-center; }

2.5 私有变量 / 函数 / Mixin ​

规则：名字以 _ 或 -（或其组合）开头的函数、mixin、变量都是模块私有的——外部文件即使用 @use 也访问不到。

💡 一个容易踩的坑：Sass 变量本来就以 $ 开头，所以私有变量写成 $_name 或 _name；但函数/mixin 名里不能出现 $，所以它们的私有前缀就是 _xxx（不要写 $_xxx，会报 Expected identifier）。

scss
// _mixins.scss
@use 'sass:math';

// 私有函数（_ 前缀）：外部拿不到
@function _internal-calc-padding($scale) {
  @return math.multiply(4px, $scale);
}

// 私有变量（$_ 或 _ 前缀都可以）
$_INTERNAL_BASE: 4px;

// 公开 mixin：但内部调用了私有函数
@mixin spacing-token($scale: 1) {
  padding: _internal-calc-padding($scale);
}
scss
// main.scss
@use 'mixins';
.card { @include mixins.spacing-token(2); }   // ✓ 公开的 spacing-token 可用
// mixins._internal-calc-padding   → ❌ 编译错误：私有成员不可外部访问
// mixins.$_INTERNAL_BASE           → ❌ 编译错误：私有变量不可外部访问

这个设计彻底杜绝了老 Sass 里改函数名时全局爆炸的问题——你可以安全地重构私有实现，不影响外部消费方。

2.6 @forward + @use 在同一文件的顺序 ​

Dart Sass 规定：@forward 必须在 @use 之前，否则编译错误。理由很简单——转导"对外"的 API 应该先于"对内"的依赖。

scss
// ✗ 错误顺序
@use 'sass:math';
@forward 'tokens';   // ❌ 编译错误

// ✓ 正确顺序
@forward 'tokens';
@forward 'mixins';
@use 'sass:math';   // 本文件内部才需要 math，对消费方不暴露

2.7 @import 与 @use 不能混用 ​

一旦某个文件用了 @use，它就进入"模块模式"——不能再对它用 @import，也不能在模块文件里 @import 其他文件。反之亦然：老的纯 @import 文件里不能写 @use。

迁移时官方推荐的路径：

  1. 先改入口 main.scss：把所有 @import 改成 @use；
  2. 逐步把每个 partial 里的 @import 改成 @use；
  3. 同时修复命名空间引用（_tokens 里的 $primary 在外部要写成 tokens.$primary，或者用 as * 保持原样）。

2.8 Tailwind v4 的官方不兼容声明（2025 年） ​

这是 2025 年的重要变化，必须了解：Tailwind CSS v4（2024 年 11 月发布）引入了自己的原生 CSS 变体语法（@variant、@theme、@source 指令），而它本身就是一个独立的预处理器。

Tailwind v4 官方不建议也不兼容与 Dart Sass 混用，原因：

  1. Tailwind v4 有自己的 AST 解析器，它不认识 Sass 的 @use / @forward / $variable 等语法；
  2. Vite/Webpack 里的处理链如果先跑 Sass 再跑 Tailwind，Tailwind 扫 .scss 文件时看不到任何 @apply、@theme 指令（因为它们在 Sass 编译阶段会被展开）；
  3. 官方 FAQ 明确："Use one or the other, not both."

混合方案的规避（如果必须同时用）：

scss
// ✗ 不要这样——Tailwind 先扫 main.scss，看到的是未展开的 @use，懵了
@use 'tokens' as *;
@tailwind base;
.card { color: $primary; @apply p-4; }

// ✓ 规避方案：先 Sass 编译 CSS，再让 Tailwind 处理 CSS 产物
// package.json
{
  "scripts": {
    "build:sass": "sass src/styles/main.scss dist/raw.css",
    "build:tw": "tailwindcss dist/raw.css -o dist/final.css",
    "build": "npm run build:sass && npm run build:tw"
  }
}
// 注意：Tailwind 的 @theme/@variant 要写在纯 CSS 文件里，Sass 只管自己那部分

选型决策树：

  • 项目需要设计系统 token、复杂控制流、mixins 封装 → 选 Dart Sass；
  • 项目需要快速原型、utility-first、动态变体 → 选 Tailwind v4；
  • 团队规模 ≤ 5 人、无复杂设计系统 → 二选一，不要混用；
  • 大型企业级项目 → 用 Tailwind v4 做快速原型 + Dart Sass 做核心组件库，按上述规避方案构建。

@use / @forward 在 standalone.js 里可以用，但需要给 includePaths 配置让编译器能找到被导入的文件。单文件 HTML 里通常用 @use 'sass:math' 这种原生模块就够了。

4. 使用场景示例 ​

4.1 设计库的公共 API 文件 ​

scss
// src/styles/abstracts/_all.scss

// 先 forward（对外暴露）
@forward 'tokens' as *;       // 所有 $color-*、$spacing-*、$radius-* 公开
@forward 'breakpoints' show $bp-sm, $bp-md, $bp-lg;  // 只暴露三个公开断点
@forward 'mixins' show flex-center, reset-focus, clamp-text;  // 只暴露三个工具 mixin

// 再 use（本文件内部才需要，不对消费方暴露）
@use 'sass:math';

// 本文件自己的内部函数
@function _private-ratio($w, $h) {
  @return math.div($w, $h);
}

4.2 消费方的 main.scss ​

scss
// src/styles/main.scss

@use 'abstracts/all' as *;
@use 'base/reset';
@use 'base/typography';
@use 'components/button';
@use 'components/card';
@use 'components/form';
@use 'utilities/spacing';
@use 'utilities/visibility';

4.3 Vite 全局注入 tokens 的正确姿势 ​

ts
// vite.config.ts
css: {
  preprocessorOptions: {
    scss: {
      // ✗ 老写法（直接 @import，会产生废弃警告）
      // additionalData: `@import "@/styles/abstracts/tokens";\n`;

      // ✓ 新写法（@use + as * 自动命名空间）
      additionalData: `@use "@/styles/abstracts/tokens" as *;\n`,
    },
  },
},

4.4 带配置变量的模块（with） ​

scss
// abstracts/_theme.scss
$primary: #3b82f6 !default;
$radius: 8px !default;
$scale: 1 !default;

.card {
  color: $primary;
  border-radius: $radius;
  font-size: 1rem * $scale;
}
scss
// main.scss
// 给 theme 模块传参（覆盖默认值）
@use 'abstracts/theme' with (
  $primary: #0ea5e9,
  $radius: 12px,
  $scale: 1.1,
);

5. 实际应用案例分析 ​

5.1 50+ SCSS 文件的大型 SaaS 前端迁移实录 ​

背景：某 2019 年启动的 SaaS 产品，52 个 SCSS 文件全部用 @import，存在：

  • 全局变量 $z-index-modal 被 3 个文件意外覆盖，出现层级错乱 bug；
  • @import 'mixins' 在 17 个文件里重复出现，编译时 mixin 展开 17 次；
  • 新人第一次上手分不清"哪个文件应该先 import"。

迁移步骤：

步骤动作耗时
1升级 Dart Sass 到 1.85，跑一遍，收集所有 deprecation warning30 min
2把顶层 5 个聚合文件改成 @forward 公开 API2h
3把组件文件里的 @import 改成 @use + 命名空间6h（52 文件）
4修复命名空间引用（$primary → tokens.$primary 或 as *）4h
5跑全量视觉回归 + unit test2h
总计14.5h ≈ 2 个工作日

收益：

  • 编译时间从 2.1s 降到 0.8s（-62%），开发热更新感知明显；
  • 全量变量冲突类 bug 从每 2 周 1–2 个降到 0；
  • 新人 onboarding 文档从 8 页 缩到 2 页。

5.2 开源库的公开 API 设计（GitHub Primer CSS） ​

Primer CSS（GitHub 官方设计系统）的 SCSS 结构用了很典型的 @forward 分层：

src/
├── primer.scss                  ← 总入口
├── _index.scss                  ← @forward 所有公开模块
├── utilities/
│   ├── _index.scss              ← @forward utilities/*
│   └── _utilities.scss
├── components/
│   ├── _index.scss
│   ├── _button.scss
│   └── _card.scss
└── support/                     ← 内部辅助层，不对外 forward
    ├── _breakpoints.scss
    └── _spacing.scss
scss
// primer.scss
@forward 'index' as *;   // 公开 API

// components/_index.scss
@forward 'button';
@forward 'card';
// ⚠️ 注意：support/* 没有被 forward——外部消费方不可用

消费方只需要：

scss
@use 'primer' as *;
.btn { @include button; }   // 所有 Primer 公共 mixin 都在根命名空间

模块加载继续 @import 'tokens'（废弃警告 + 污染）@use 'tokens'（命名空间）或 @use 'tokens' as *（全局但显式）
私有成员随便起变量名，依赖"别人不要改我这个"_private-func() / $_temp-state（函数/mixin 用 _ 前缀；变量可以用 $_ 或 _ 前缀）
模块 API对外 forward 所有内部实现用 show / hide 精确控制对外暴露的成员列表
混合 Tailwind@use 'tokens'; @tailwind base;（Tailwind 看不懂）二选一；必须混用则先 Sass 后 Tailwind（见 2.8）
文件命名variables.scss（没有下划线，可能被单独编译）_variables.scss（partial 前缀约定）
除法$half: $width / 2（废弃警告）@use 'sass:math'; $half: math.div($width, 2)
顺序@use 'sass:math'; @forward 'tokens'@forward 'tokens'; @use 'sass:math'

6.2 命名空间陷阱：你以为用的是这个变量 ​

scss
// ✗ 陷阱
@use 'theme';
@use 'legacy-config';   // 老文件里有个叫 $primary 的变量

// main.scss
.btn { color: $primary; }   // ❌ 编译错误！没有 `as *` 所以没有全局 $primary
// 你以为 $primary 来自 'legacy-config'，但其实两个模块的 $primary 都在命名空间里
.btn { color: theme.$primary; }    // ✓ 明确
.btn { color: legacy-config.$primary; }  // ✓ 明确

6.3 as * 的正确用法 ​

@use 'tokens' as * 会把 tokens 的所有公开成员暴露到当前文件的全局作用域。这适用于：

  • 你只导入 tokens 这一个文件，不存在冲突；
  • 在不转发给别人的消费文件（组件）里使用；
  • 入口 main.scss 这种"最后一站"文件。

不要在设计库的聚合层（abstracts/_all.scss）里用 as * 然后再 @forward ——那样你就失去了模块隔离的意义。

6.4 文件查找路径（load-path） ​

当 @use 'tokens' 找不到文件时：

bash
# CLI 指定查找根目录
npx sass main.scss -o output.css --load-path=src/styles

# Vite 里自动从项目根和各个 src 子目录查找，一般不用额外配置
# 但用 alias（比如 @/）时要同步配置 vite.config.ts 的 resolve.alias

6.5 @forward 的别名传播 ​

scss
// abstracts/_all.scss
@forward 'tokens' as t-*;

// main.scss
@use 'abstracts/all' as *;
.btn { color: t-$primary; }    // ✓ 可以消费带前缀的
// 但原来的 tokens.$primary 不可用了
