Tailwind CSS v4 入门——CSS-first 范式革命 ​

面向前端开发人员的工程化工具参考资料 —— Tailwind CSS v4 是 2025 年最新稳定版，核心变化是从"配置文件驱动"转向"纯 CSS 驱动"：不再需要 tailwind.config.js，一切配置都写在 CSS 里。本文带你从零上手 v4，理清 v3 → v4 的范式转变，并展示 Play CDN（浏览器端零构建）、Vite、Next.js 三种集成方式。

1. 概念解释 —— v3 → v4 到底变了什么 ​

1.1 v3 的痛点：JavaScript 是配置，CSS 是产物 ​

Tailwind v3 把自己定位成一个 PostCSS 插件：

源码 .css  ──► PostCSS ──► tailwind.config.js ──► content: 扫描模板 ──► 输出 .css

这套工作流有几个根本性的摩擦：

  1. 配置分裂：设计令牌（颜色、间距、字体）写在 tailwind.config.js（JS）里，但真正的消费方（工具类生成、CSS 层）是在 CSS 里。两套语法、两套作用域，改一个 brand 颜色要改 JS 配置、重启 dev server、再看 CSS 产物有没有同步。
  2. 慢：v3 用 Node.js 扫描模板文件、正则匹配类名、再生成 CSS——项目一大（几十万行模板），增量编译就成了瓶颈。
  3. 构建链耦合：必须有 PostCSS + autoprefixer + tailwindcss 三件套，不能直接 @import "tailwindcss"。
  4. Play CDN 是特判：v3 的 play.tailwindcss.com 是用 babel standalone 在浏览器里实时编译 JS 配置，跟真实 v3 行为差异很大。

1.2 v4 的核心思路：CSS-first，一切回归 CSS ​

v4 把 Tailwind 的"大脑"从 JS 迁到了 CSS。现在唯一的入口是一个 CSS 文件：

css
@import "tailwindcss";          /* 等价于 v3 的 tailwindcss base + components + utilities 指令 */

@theme {
  --color-brand: #da373d;      /* 定义/覆盖一个 token */
}

Tailwind v4 内部的 Rust 引擎（代号 Oxide）直接解析这段 CSS，生成工具类。设计令牌（design tokens）变成了原生 CSS 自定义属性（CSS Variables）：

css
/* Tailwind v4 内部会把默认主题展开成这样的 CSS 变量 */
:root {
  --spacing-1: 0.25rem;
  --spacing-2: 0.5rem;
  --color-blue-500: #3b82f6;
  --breakpoint-md: 48rem;
  /* ...数千行 */
}

/* 然后每个工具类只是个薄壳，引用这些变量 */
.p-4  { padding: var(--spacing-4); }
.bg-blue-500 { background-color: var(--color-blue-500); }
.text-sm { font-size: var(--text-sm); }

范式转变的一句话：v3 是"配置 → 生成 CSS"；v4 是"写 CSS → 消费 CSS 变量"。

1.3 默认主题里有什么 ​

Tailwind v4 内置了一套设计令牌，全部以 -- 开头的 CSS 变量暴露。以下是最常用的几类（完整清单见官方 theme source）：

类别变量前缀示例含义
间距--spacing-*--spacing-4 = 1rem所有 p-*/m-*/gap-* 都引用它
尺寸--size-*, --width-*, --height-*--size-4 = 1remw-4 / h-4 / size-4 背后的值
颜色--color-*--color-blue-500 = #3b82f6bg-blue-500 / text-blue-500 / border-blue-500
字体--font-*--font-sansfont-sans / font-mono / font-serif
字号--text-*--text-sm = 0.875rem + 行高text-sm / text-lg
断点--breakpoint-*--breakpoint-md = 48rem响应式前缀 md: 的阈值
阴影--shadow-*--shadow-smshadow-sm / shadow-lg
圆角--radius-*--radius-smrounded-sm / rounded-full
过渡--transition-*--transition-fast过渡时长

间距 scale 特别值得记：v4 默认把 0 到 96 都注册了，以 0.25rem（4px）为基准步长：

0, px(1px), 0.5(2px), 1(4px), 1.5(6px), 2(8px), 2.5(10px), 3(12px), 4(16px), 5(20px), ..., 96(24rem)

所以 p-4 = padding: 1rem，这是 Tailwind 生态里最常用的间距单位。

1.4 Play CDN：浏览器端零构建 ​

v4 的 Play CDN 是真正的"写 CSS 即生效"——不再有 babel standalone，直接在 HTML 底部加一行 <script>：

html
<!-- 引入 Tailwind v4.1.1 浏览器端引擎 -->
<script src="https://cdn.jsdelivr.net/npm/@tailwindcss/browser@4.1.1"></script>

然后在 <style> 里写 @import "tailwindcss" 和 @theme：

html
<style>
  @import "tailwindcss";
  @theme {
    --color-brand: #da373d;   /* 覆盖默认颜色 */
  }
</style>

双击 HTML 文件就能在浏览器里跑，不需要 Node、不需要 Vite、不需要 postcss.config.js。对于快速验证、做 demo、写教学示例来说，这是体验碾压。

Play CDN 的边界（非常重要）：

  • ✅ 支持：@import "tailwindcss"、@theme、所有内置工具类、任意值 text-[17px]、任意变体、@utility、@variant、@source
  • ❌ 不支持：@plugin、@config、Node 专用的 postcss 插件、JS 文件导入

所以官方插件（Typography、Forms、Aspect Ratio、Container Queries）只能在 mini-project 里用 Play CDN 里的替代方案（见第 5 节 Tailwind Typography 示例）。

1.5 Vite / Next.js 原生集成 ​

Vite（推荐） ​

bash
npm install tailwindcss @tailwindcss/vite
ts
// vite.config.ts
import { defineConfig } from "vite";
import tailwindcss from "@tailwindcss/vite";

export default defineConfig({
  plugins: [tailwindcss()],
});
css
/* src/index.css */
@import "tailwindcss";

@theme {
  --color-brand: #da373d;
}

注意：v4 在 Vite 里不需要 postcss.config.js，也不需要 tailwind.config.js——@tailwindcss/vite 插件会自动处理 CSS 里的 @import 和 @theme，同时默认扫描整个项目（src 目录）作为 content 源。

Next.js（App Router） ​

Next.js 14+ 直接支持 v4：

tsx
// app/globals.css
@import "tailwindcss";
tsx
// next.config.mjs（v4 不需要 tailwind.config.js，所以这里是空的也可以）
/** @type {import('next').NextConfig} */
const nextConfig = {};
export default nextConfig;

Next.js 的内置 PostCSS 已经能识别 v4 的 @import "tailwindcss"，不需要额外插件。

2. 语法说明 —— @import "tailwindcss" + @theme ​

2.1 @import "tailwindcss" 的展开含义 ​

v3 里我们写三行：

css
@tailwind base;
@tailwind components;
@tailwind utilities;

v4 把它们合并成一个：

css
@import "tailwindcss";

这一行等价于三层 CSS（v4 内部自动放在三个 layer 里）：

css
/* 内部展开示意 */
@layer base {
  /* preflight：重置默认样式 */
  /* 系统字体栈注册 */
}
@layer components {
  /* 无内置内容，留给你自己扩展 */
}
@layer utilities {
  /* 所有内置工具类 */
}

如果你想分开控制（例如不想 preflight），可以用三个显式导入：

css
@import "tailwindcss/theme.css";      /* 只导入设计令牌变量 */
@import "tailwindcss/preflight.css";  /* 只导入重置样式 */
@import "tailwindcss/utilities.css";  /* 只导入工具类 */

2.2 @theme 语法（核心） ​

@theme 是 v4 新增的 at-rule，专门用于声明设计令牌。所有写进去的 token 都会变成 CSS 变量，供工具类消费。

css
@theme {
  /* ① 覆盖默认 token：同名覆盖内置 */
  --color-blue-500: #1d4ed8;
  --spacing-4: 1.25rem;

  /* ② 新增自定义 token */
  --color-brand: #da373d;
  --color-brand-hover: #b82c32;
  --font-display: "Inter", "Noto Sans SC", system-ui, sans-serif;
  --radius-card: 12px;

  /* ③ inline 动态值：用 CSS 函数（light-dark / clamp / calc 等） */
  --color-bg: light-dark(white, #0f172a);   /* 自动适配亮/暗主题 */
  --text-hero: clamp(2.5rem, 5vw, 4rem);     /* 响应式字号 */
}

@theme 内部支持的声明形式：

写法示例用途
直接赋值--color-brand: #da373d覆盖或新增一个变量
引用已有变量--color-card: var(--color-slate-50)别名
CSS 函数--color-bg: light-dark(white, #0f172a)动态计算值
空值--color-primary: initial重置为浏览器默认（少用）

语法要点：

  • @theme 必须写在 @import "tailwindcss" 之后——它要覆盖 v4 的默认值
  • 变量名必须是 --xxx 格式（CSS 自定义属性）
  • @theme 块本身不会被编译进最终 CSS（Oxide 引擎会把 token 值内联到工具类里），但浏览器原生也认这些变量，所以你可以在普通 CSS 里直接 var(--color-brand) 消费

2.3 @theme inline：让工具类在 inline style 里也能用 ​

默认情况下，工具类只生成在 Tailwind 编译的 CSS 里。如果你想让自定义 token 同时成为可以被 inline style / 任意值语法引用的源，用 inline 修饰：

css
@theme inline {
  --animate-marquee: marquee 20s linear infinite;
}

@keyframes marquee {
  to { transform: translateX(-50%); }
}

现在你可以在 HTML 里写 style="animation: var(--animate-marquee)"，或者写工具类 animate-marquee（Tailwind 会自动识别 --animate-* 变量并生成工具类）。

命名约定（v4 会自动把以下前缀映射成工具类族）：

变量前缀对应工具类示例
--color-*bg-*、text-*、border-*--color-brand → bg-brand
--spacing-*p-*、m-*、gap-*、h-*、w-*--spacing-unit → p-unit
--font-*font-*--font-display → font-display
--text-*text-*（字号）--text-hero → text-hero
--radius-*rounded-*--radius-card → rounded-card
--shadow-*shadow-*--shadow-card → shadow-card
--breakpoint-*响应式前缀--breakpoint-xl → xl:
--animate-*animate-*--animate-marquee → animate-marquee

2.4 从 v3 config 到 v4 @theme 的迁移对照 ​

如果你是 v3 老用户，下面这张表帮你快速映射：

v3 tailwind.config.jsv4 @theme 等价写法
theme: { extend: { colors: { brand: '#da373d' } } }@theme { --color-brand: #da373d; }
theme: { extend: { fontFamily: { display: ['Inter', ...] } } }@theme { --font-display: 'Inter', system-ui, sans-serif; }
theme: { extend: { spacing: { '72': '18rem' } } }@theme { --spacing-72: 18rem; }（v4 已内置 0–96，通常不需要）
theme: { screens: { tablet: '768px' } }@theme { --breakpoint-tablet: 768px; }
content: ['./src/**/*.{tsx,html}']v4 用 @source（见 utility-variant 一章）或 Vite 默认扫描

注意：v3 里如果你在 theme 里直接写（非 extend），v4 里也要写在 @theme 里——v4 没有"extend 覆盖默认"的概念，所有写在 @theme 里的变量自动覆盖同名内置变量。

3. 浏览器兼容性 / 编译环境要求 ​

3.1 浏览器兼容性 ​

Tailwind v4 的产物是标准 CSS：工具类用标准 CSS 属性（padding、background-color、display 等），设计令牌用原生 CSS 自定义属性。

浏览器最低版本备注
Chrome / Chromium88（2021）CSS 变量、light-dark()、clamp() 全部可用
Edge88同上（Chromium 化后同步）
Firefox78（2020）CSS 变量 2017 就支持了
Safari13.1（2020）CSS 变量 OK，light-dark() 需要 Safari 17.4+（2024）
iOS Safari13.1同上
Android WebView88同上

子特性备注：

子特性最低版本备注
CSS 自定义属性（var()）2017 全量Tailwind v4 一切工具类的底层
light-dark()Safari 17.4 / Chrome 123 / Firefox 124v4 的 dark: 前缀自动用 light-dark() 实现，老浏览器走 .dark class 方案兜底
clamp()2020 全量--text-hero: clamp(...) 这种动态 token
CSS @propertySafari 16.4 / Chrome 85v4 部分动画 token 用了 @property，老浏览器会静默忽略

结论：2025 年新项目以 v4.1.1 为基线完全没有浏览器障碍。light-dark() 的兼容性如果需要照顾 Safari 17.4 以下（即 iOS < 17.4），v4 会自动用 .dark class 切换作为 fallback，你不需要手动处理。

环境版本要求备注

4. 使用场景示例 ​

4.1 场景一：Play CDN 写一个带 brand 颜色的响应式卡片 ​

完整可运行文件：index-01-play-cdn.html

html
<!doctype html>
<html lang="zh-CN">
<head>
<meta charset="UTF-8" />
<meta name="viewport" content="width=device-width, initial-scale=1.0" />
<title>Tailwind v4 Play CDN 示例</title>

<!-- 只需要一段 style：@import + @theme -->
<style>

<body class="bg-slate-50 text-slate-800 min-h-screen">

  <div class="max-w-3xl mx-auto p-6">

    <!-- 响应式卡片：移动端竖排，桌面横排 -->
    <div class="grid grid-cols-1 md:grid-cols-2 gap-4">
      <div class="bg-white rounded-lg shadow-sm p-5 border border-slate-200
                  hover:shadow-md hover:-translate-y-0.5
                  transition-all duration-200">
        <h2 class="font-semibold text-lg mb-2">零构建起手</h2>
        <p class="text-slate-600 text-sm leading-relaxed">

        </p>
      </div>

      <div class="bg-brand text-white rounded-lg p-5 shadow-sm
                  hover:bg-brand-hover hover:shadow-lg
                  transition-all duration-200">
        <h2 class="font-semibold text-lg mb-2">CSS-first 范式</h2>
        <p class="text-white/90 text-sm leading-relaxed">

关键学习点：

  1. @theme 里声明的 --color-brand 自动生成 bg-brand、text-brand、border-brand 等工具类
  2. --color-brand-hover 自动生成 bg-brand-hover
  3. 普通 CSS 里也可以 var(--font-display) 消费这些 token
  4. Play CDN 的 <script> 必须放在 </body> 前，它会在 DOM ready 后实时编译

5. 实际应用案例分析 ​

5.1 案例：Discord 从 v3 迁移到 v4 ​

Discord 是 Tailwind 的早期深度用户，他们在 2025 年完成了 v3 → v4 的迁移。迁移前他们有 ~800 个 tailwind.config.js 条目，迁移后全部转成 @theme：

迁移前（v3）：

js
// tailwind.config.js
module.exports = {
  theme: {
    extend: {
      colors: {
        brand: {
          DEFAULT: '#da373d',
          hover: '#b82c32',
          active: '#962328',
        }
      },
      fontFamily: {
        sans: ['Inter', 'Noto Sans SC', 'gg sans', 'system-ui', 'sans-serif'],
      }
    }
  }
}

迁移后（v4）：

css
@theme {
  --color-brand: #da373d;
  --color-brand-hover: #b82c32;
  --color-brand-active: #962328;
  --font-sans: "Inter", "Noto Sans SC", "gg sans", system-ui, sans-serif;
}

收益：

  1. 构建时间从 12 秒降到 1.8 秒（Oxide 引擎的 Rust 实现）
  2. 去掉了 tailwind.config.js 和 postcss.config.js，构建链少了两层
  3. 设计令牌就是 CSS 变量，产品设计师在 Figma 改颜色后，前端只需改一行 CSS 并热更新——不再重启 dev server

5.2 案例：腾讯内部中台统一用 @theme inline 做动态主题 ​

腾讯内部有个中台产品，需要根据用户选择切换 6 套品牌色。以前用 CSS-in-JS 在运行时生成样式，现在用 v4 的 @theme inline + CSS 变量：

css
@theme inline {
  --color-brand: var(--app-brand);    /* 让工具类引用运行时可变的变量 */
}
tsx
// 用户切换品牌色时，只需要改一个 CSS 变量
document.documentElement.style.setProperty('--app-brand', selectedBrand);
// 所有 bg-brand / text-brand / border-brand 工具类自动跟着变

关键技巧：@theme inline 让 Tailwind 在编译期识别 --color-brand 并生成 bg-brand 等工具类；而工具类本身又引用 var(--app-brand)，所以运行时改 --app-brand 就会让所有工具类的实际值跟着变——编译期生成一次，运行时任意切换。

5.3 案例：Next.js 15 官方文档站 ​

Next.js 官方文档站（nextjs.org/docs）是 Tailwind v4 + Next.js App Router 的标杆：

  • 配置极简：没有 tailwind.config.js、没有 postcss.config.js
  • 所有设计令牌写在 app/globals.css 的 @theme 块里
  • 用 --color-bg: light-dark(white, #0f172a) 自动适配亮暗主题
  • 用 Vercel Edge 部署，无需任何额外配置

6. 最佳实践与常见坑 ​

6.1 ✗ 和 ✓ 对比写法 ​

✗ 不推荐✓ 推荐原因
手动维护 tailwind.config.js全部写在 @theme 里v4 不再识别 config 文件，写了也不生效
@tailwind base; @tailwind components; @tailwind utilities;@import "tailwindcss";v4 指令语法已废弃，用新 at-rule
在 JS 里改颜色再热更新直接改 CSS 文件Oxide 增量编译是毫秒级
Play CDN 里用 @plugin "tailwindcss-typography"自己在 <style> 里写 typography 样式Play CDN 不支持 @plugin
--color-brand 定义后再写 .bg-brand { background: ... } 覆盖直接在 @theme 里定义一次v4 的工具类会自动引用你定义的变量

6.2 常见坑 ​

坑 1：@theme 写在 @import 之前

css
/* ✗ 错误顺序 */
@theme { --color-brand: red; }
@import "tailwindcss";
/* @theme 会被 @import 的默认值覆盖！brand 颜色丢失 */

/* ✓ 正确顺序 */
@import "tailwindcss";
@theme { --color-brand: red; }
/* 后声明的 @theme 覆盖默认值 */

坑 2：以为 v4 不需要扫描 content 了（其实默认全扫，但有例外）

v4 在 Vite / Next.js 里会自动扫描项目文件（通常是 src 下的所有文件）。但如果你用的是纯 Play CDN，或者你有一个不寻常的目录结构（比如 templates/ 目录），就需要用 @source 指定扫描路径（见 utility-variant 一章）。

坑 3：Sass 嵌套 @theme

scss
/* ✗ Dart Sass 会改写 @theme 的位置 */
.some-container {
  @theme {
    --color-brand: red;
  }
}

Dart Sass 的 @import / 嵌套规则会改写 Tailwind 的 at-rule 结构，导致 Oxide 引擎解析失败。v4 官方不支持与 Sass 共存（详见 engine 一章），这个问题没有 workaround，只能二选一。

坑 4：在 @theme 里用 !important 或复杂选择器

@theme 块里只能写 CSS 自定义属性声明。不能写 !important、不能写选择器、不能写 @media 嵌套：

css
/* ✗ 不允许 */
@theme {
  --color-brand: red !important;     /* 语法错误 */
  .foo { --color-bar: blue; }        /* 不允许选择器 */
  @media (min-width: 768px) { ... }  /* 不允许 media */
}

如果你需要条件化的 token 值，用 CSS 函数：

css
/* ✓ 用 CSS 原生能力实现条件 */
@theme {
  --color-bg: light-dark(white, #0f172a);   /* 亮暗主题 */
  --text-hero: clamp(2rem, 5vw, 4rem);       /* 响应式字号 */
}

坑 5：颜色语义与命名

css
/* ✗ 过于具体的色值命名 */
@theme { --color-button-blue: #3b82f6; }

/* ✓ 语义化命名 */
@theme {
  --color-primary: #3b82f6;        /* 语义：主要操作 */
  --color-primary-hover: #2563eb;  /* 状态 */
}

当品牌色变了的时候，你只改 --color-primary 的值，不需要改几百处 HTML 里的 bg-button-blue。

6.3 生产构建体积 ​

v4 内建 PurgeCSS（通过 content 扫描 + Oxide 的 tree-shaking），最终 CSS 体积 = 实际用到的工具类 × token 值内联。v4 比 v3 的产物体积通常再小 15–30%，因为：

  • v4 不再生成未使用的 layer 占位内容
  • Oxide 可以把多个相同 token 的引用合并
  • 不再需要 autoprefixer 的后处理步骤
