1. 概念解释 —— v4 的核心到底变了什么 ​

1.1 Oxide 引擎：Rust 重写的编译器 ​

Tailwind v3 是用 JavaScript 写的，运行在 Node.js 上：

源码 → Node 进程 → PostCSS 管道 → tailwindcss 插件 → autoprefixer → 输出 CSS

v4 直接重写成了一个 Rust 二进制，代号 Oxide：

源码 → Oxide（Rust）→ 输出 CSS

关键设计决策：

  1. Rust 原生实现：不依赖 Node、不依赖 PostCSS、不依赖 autoprefixer。Oxide 是一个独立的、无依赖的编译器。
  2. CSS 优先的输入格式：不再有 JS config 文件。所有配置都是 CSS at-rule（@theme、@utility、@variant、@source、@plugin）。
  3. 更快的扫描算法：v3 用正则匹配模板里的类名，v4 用 AST 解析器（Tree-sitter）精确提取。
  4. 内建 PurgeCSS：不再依赖独立包，tree-shaking 是 Oxide 的原生能力。

1.2 性能数据 ​

官方给出的基准测试（真实项目模板）：

指标v3v4提升
首次冷构建（clean build）12.4s2.1s5.9×
增量构建（改一行 CSS）1.8s18ms100×
增量构建（改一个模板文件）2.1s32ms65×
生成的 CSS 体积142 KB98 KB-31%

为什么这么快：

  • Rust 本身比 Node 快 5–10×
  • Oxide 不用重启 PostCSS 管道就能增量更新
  • AST 解析比正则快且准确
  • 不加载 autoprefixer / postcss 的 overhead

1.3 "Tailwind CSS itself is your preprocessor" ​

这是 Tailwind 官方在 v4 发布时在文档里说的原话：

Tailwind CSS itself is your preprocessor — you shouldn't use Tailwind with Sass.

出处：https://tailwindcss.com/docs/compatibility

这句话的背景：

  • v4 已经内置了变量（CSS Variables）、嵌套（v4 的工具类展开后是平铺 CSS，但你写 @layer + 嵌套类的写法支持良好）、条件（light-dark()）、计算（calc()）——Sass 的核心能力 v4 都有了
  • 更重要的是，Dart Sass 的编译器会改写 Tailwind 的 at-rule 位置，导致 Oxide 无法正确解析 @theme

1.4 与 Sass 不兼容的技术原因 ​

具体来说，Dart Sass（现在最流行的 Sass 实现）会对 CSS 文件做以下改写：

改写 1：@import 的位置 ​

scss
/* 你写的 scss */
@theme {
  --color-brand: #da373d;
}

@import "tailwindcss";

Dart Sass 会把所有 @import 提升到文件最顶部（CSS 规范要求），最终 Oxide 看到的是：

css
@import "tailwindcss";

@theme {
  --color-brand: #da373d;
}

这个顺序是正确的（@import 在前，@theme 在后），Oxide 能正确解析。所以 @import 位置问题其实不算坑——除非你在 嵌套规则里 写 @theme。

改写 2：嵌套 @theme 被展开 ​

scss
/* 你写的 scss */
.container {
  @theme {
    --color-brand: #da373d;
  }
}

Dart Sass 会把它展开成：

css
/* 这种结构 Oxide 识别不了 */
.container { @theme { --color-brand: #da373d; } }

@theme 必须是顶层 at-rule，不能嵌套在选择器里。这是 v4 的硬性要求。

改写 3：Sass 变量与 Tailwind 变量混淆 ​

scss
/* Sass 变量（编译期消失） */
$brand-color: #da373d;

/* Tailwind v4 变量（CSS 变量，运行时存在） */
@theme {
  --color-brand: $brand-color;  /* Dart Sass 会把 $brand-color 替换成 #da373d，这行 OK */
}

看似没问题，但如果你想反过来：

scss
@theme {
  --color-brand: #da373d;
}

/* Sass 里想引用 Tailwind 变量 */
$brand-color: var(--color-brand);  /* ❌ Sass 不支持 CSS var() 作为变量值 */

Sass 变量是编译期常量，CSS var() 是运行时值——这两者根本不在同一个世界里。Sass 里写 $brand-color: var(--color-brand) 在 Dart Sass 里是语法错误或不会被你预期的方式处理。

改写 4：Play CDN 完全不支持 Sass ​

Play CDN 是浏览器端纯 JavaScript 引擎，不支持加载 .scss 文件（它只认标准 CSS）。所以在 Play CDN 里你根本没法用 Sass，只能写纯 CSS。

2. 语法说明 —— @plugin、@config、以及不能做的事 ​

2.1 @plugin —— 加载 npm 包或本地 JS 插件 ​

css
/* 加载官方插件 */
@plugin "@tailwindcss/typography";
@plugin "@tailwindcss/forms";

/* 加载第三方插件 */
@plugin "tailwindcss-animate";

/* 加载本地自定义插件 */
@plugin "./my-tailwind-plugin.js";

前提：对应的 npm 包必须先安装：

bash
npm install @tailwindcss/typography
npm install tailwindcss-animate

Play CDN 不支持 @plugin——浏览器端没有 npm 环境。

2.2 @plugin 与 @config（legacy 配置兼容） ​

v4 为了兼容 v3 的 tailwind.config.js，提供了一个 @config 指令：

css
@config "./tailwind.config.js";
@import "tailwindcss";
@theme { /* 覆盖 config 里的值 */ }

这在迁移期有用，但新项目不应该用——直接用 @theme 写一切。

2.4 Tailwind Typography 插件实战 ​

完整骨架见 mini-project/。

src/index.css ​

css
@import "tailwindcss";

/* 加载 Typography 插件 */
@plugin "@tailwindcss/typography";

@theme {
  --color-primary: #da373d;
}

/* 自定义 Typography 样式 */
@layer components {
  .prose {
    /* Typography 插件已经给 .prose h1-h6/p/ul/ol/blockquote 等写了默认样式 */
    /* 你可以用 @theme 里的 token 覆盖 */
    max-width: none;
  }
}

npm 安装 ​

bash
npm install tailwindcss @tailwindcss/vite @tailwindcss/typography

用法 ​

tsx
export default function BlogPost() {
  const markdown = `# Tailwind v4 入门\n\n这是一篇文章……`;
  const html = renderMarkdown(markdown);  // 比如用 react-markdown

  return (
    <article className="prose prose-lg prose-slate max-w-none mx-auto">
      <div dangerouslySetInnerHTML={{ __html: html }} />
    </article>
  );
}

prose 类会自动给内部所有 h1-h6 / p / ul / ol / blockquote / code / img / table 等元素套上好看的排版样式。

2.5 Typography 的 @theme 配置 ​

Typography 插件的设计令牌也在你的 @theme 里：

css
@theme {
  /* 覆盖 Typography 的标题颜色 */
  --typography-heading-color: var(--color-slate-900);
  /* 覆盖链接颜色 */
  --typography-a-color: var(--color-primary);
}

这样 Typography 的样式就会跟着你的设计系统走。

5.3 案例：与 Sass 混用的风险场景（反面教材） ​

一个团队想"保留 Sass 的 mixin + 变量，同时用 Tailwind v4"，于是把所有 CSS 重命名成 .scss：

scss
/* main.scss */

/* ① Sass 变量 */
$brand-color: #da373d;
$spacing-unit: 8px;

/* ② Tailwind v4 指令 */
@import "tailwindcss";

/* ③ Tailwind @theme */
@theme {
  --color-brand: $brand-color;       /* Dart Sass 会把 $brand-color 替换成 #da373d — 这行 OK */
  --spacing-header: calc($spacing-unit * 8);  /* 也 OK */
}

/* ④ Tailwind @utility */
@utility fancy {
  &:hover { transform: scale(1.05); }   /* 也 OK */
}

/* ⑤ 嵌套规则里加 @theme（❌ 问题在这） */
.container {
  @theme {
    --color-child: blue;   /* Dart Sass 展开后变成嵌套，Oxide 不识别 */
  }
}

运行结果：

  • ④ 和 ③ 的部分（顶层）正常工作 ✅
  • ⑤ 的嵌套 @theme 被 Dart Sass 展开成无效结构，Oxide 静默忽略 ❌
  • Dart Sass 的 @import "tailwindcss" 会放在文件最顶部（正确位置），但如果你在 SCSS 里写 @use "tailwindcss" 就不行（Tailwind 不认 @use）

教训：如果你必须用 Sass，把 Tailwind v4 的部分单独放在 .css 文件里，不要混在 .scss 里：

styles/
├── tailwind.css       ← @import "tailwindcss" + @theme + @utility
├── mixins.scss        ← 只有 Sass 特有的 mixin / @include
└── main.scss          ← @use "./mixins"; @import "./tailwind.css";

这样 Tailwind 的部分保持纯 CSS，Oxide 能正确解析；Sass 的部分只做 mixin 和变量（编译期替换），不干预 Tailwind 的结构。

6. 最佳实践与常见坑 ​

6.1 ✗ 和 ✓ 对比写法 ​

✗ 不推荐✓ 推荐原因
在 .scss 里混写所有东西Tailwind v4 放 .css，Sass 放 .scss，分开避免 Dart Sass 改写 Tailwind 结构
Play CDN 里写 @plugin "@tailwindcss/typography"Play CDN 里手写 .prose 样式Play CDN 不支持 Node 环境
新项目写 tailwind.config.js + @config新项目只用 @themev4 不需要 legacy 配置
忘记 npm install @tailwindcss/typography 就写 @plugin@plugin 之前先 install没有对应的包，Oxide 会报错
在 @theme 里写 Sass 变量引用嵌套值@theme 里只写顶层值Dart Sass 嵌套会导致 Oxide 解析失败

6.2 常见坑 ​

坑 1：@plugin 的版本兼容性

Tailwind v4 官方插件的版本号也跟着 v4 走：

bash
# ✗ 装到 v3 版本（peerDependencies 不兼容 v4）
npm install @tailwindcss/typography    # 可能是 v3.x

# ✓ 显式指定 v4 版本
npm install @tailwindcss/typography@latest

查看插件的 peerDependencies 是否包含 tailwindcss >= 4。

坑 2：Dart Sass 处理 @import "tailwindcss" 的问题

Dart Sass 会把所有 @import 提升到文件顶部。如果你在 SCSS 里写：

scss
/* 先写了一堆 Tailwind 配置 */
@theme {
  --color-brand: #da373d;
}

/* 再导入 tailwindcss */
@import "tailwindcss";

Dart Sass 会把它重排成：

scss
@import "tailwindcss";   // 被提升到顶部

@theme {
  --color-brand: #da373d;
}

这个恰好是正确的顺序（@import 在前，@theme 在后），所以没问题。

但如果你用的是 v3 遗留的三指令写法（@tailwind base;）：

scss
@theme { --color-brand: #da373d; }
@tailwind base;          /* v3 语法 */
@import "tailwindcss";   /* v4 语法 */

Dart Sass 提升后会把 @import "tailwindcss" 放在顶部，但 @tailwind base（v3 指令）会留在原位。v4 不再识别 @tailwind base 这种指令，所以会被忽略。v4 新项目只用 @import "tailwindcss"，不用 @tailwind 指令。

坑 3：Play CDN 用外部 CSS 变量但忘了 @theme inline

html
<!-- Play CDN 里引入外部文件 -->
<link rel="stylesheet" href="tokens.css" />  <!-- tokens.css 里有 :root { --color-brand: ... } -->

<style>
  @import "tailwindcss";

  /* ✗ 这样不行——Tailwind 编译期没看到 --color-brand */
  .my-div { background-color: var(--color-brand); }
  /* 不会自动生成 bg-brand 工具类 */

  /* ✓ 在 @theme inline 里引用 */
  @theme inline {
    --color-brand: var(--color-brand);
  }
  /* 现在自动生成 bg-brand */
</style>

坑 4：@source 路径在 Play CDN 里的表现

Play CDN 默认扫描当前 HTML 文件。如果你有外部 JS 文件需要扫描，用 @source 声明：

css
/* Play CDN 里可以用相对路径引用外部文件 */
@source "./script.js";

但注意：Play CDN 是浏览器端，它能 fetch 到的文件取决于 CORS 和本地文件协议限制。本地文件 file:// 协议下 fetch 外部 JS 可能被浏览器拦截。建议 Play CDN 示例把所有 class 直接写在 HTML 里，不要依赖外部扫描。

坑 5：@import 必须是 CSS 文件，不能是 JS

v4 的 @import "tailwindcss" 里的字符串是 CSS 模块名（被 Oxide 识别为内置别名）。但如果你想 import 普通 CSS 文件：

css
@import "./custom.css";          /* ✓ OK，相对路径 */
@import "some-npm-package";     /* ✓ 在 mini-project 里 OK（Node 解析），Play CDN 不支持 */

6.3 Tailwind vs Sass 选型决策树 ​

开始
 │
 ├─ 新项目？
 │   ├─ 是 → 纯 Tailwind v4（@theme + @utility + @variant）
 │   │        理由：v4 已经内置了变量、嵌套、条件、计算
 │   │
 │   └─ 否 → 已有 Sass mixin 库或复杂逻辑？
 │       ├─ 是 → 共存：Tailwind v4 写 CSS 文件，Sass 写 .scss，分开 @import
 │       └─ 否 → 纯 Tailwind v4，无需 Sass
 │
 ├─ 需要动态逻辑（循环生成 class 等）？
 │   └─ Tailwind v4 @plugin（写 JS 插件）→ 比 Sass @for 更强
 │
 ├─ Play CDN / 教学示例 / 快速验证？
 │   └─ 纯 Tailwind v4 单文件 HTML，不能用 Sass
 │
 └─ 总结：
     Tailwind v4 覆盖 95% 场景
     Sass 只在需要非常复杂的编译期逻辑时保留
     混用时严格分文件

6.4 性能最佳实践 ​

  • 默认配置：不要为了"更快"去关 PurgeCSS。v4 内建的 PurgeCSS 是 Oxide 原生能力，关掉反而让产物变肥
  • 增量构建：v4 的 Oxide 引擎会自动做——不需要 --watch 之外的额外配置
  • CSS 体积：v4 默认产物已经是 minified 的 gzip 25KB 量级
  • 不要手动添加 postcss.config.js 和 autoprefixer——v4 不需要，加了只是浪费构建时间
