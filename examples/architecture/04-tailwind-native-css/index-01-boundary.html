Tailwind 与原生 CSS 的边界

令牌做桥，组件层立契约，工具层做微调。

① 分层与令牌桥接

/* 顺序决定覆盖关系 */
@layer theme, base, components, utilities;

@layer theme {
  :root { --color-action: #2563eb; --space-4: 16px; }
}

@layer components {
  .btn { background: var(--color-action); padding-inline: var(--space-4); }
}

@layer utilities {
  .px-5 { padding-inline: var(--space-5); }
}

`@theme` 输出变量，工具类与组件 CSS 消费同一份令牌，避免两套色值。

② 工具类覆盖组件契约

.btn 在 components 层给出默认 16px 内边距；.px-5 在 utilities 层给出 20px。 工具类在声明顺序上更高，因此覆盖是预期行为——这正是 Tailwind 的微调机制。

③ 令牌间距 vs 任意像素值

推荐使用令牌：px-5 → --space-5

所有按钮共享同一档间距，改令牌即可全局调整。

慎用任意值：p-[13px]

13px 绕过令牌，无法被主题/密度系统统一调整，评审时应回填到令牌。

④ 边界清单

工具类：间距、对齐、一次性排版、局部颜色。
组件 CSS：结构、状态（hover/focus/disabled/loading）、容器查询、:has()、伪元素装饰。
令牌：颜色、间距、圆角、字体、阴影的唯一来源。
